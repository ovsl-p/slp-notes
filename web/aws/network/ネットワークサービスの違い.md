# ネットワークサービスの違い

## ひとことで

「どこで受けるか」「何で振り分けるか」「どこまで経路を流すか」の3つで、ネットワークのサービスは分かれる。

## なぜ効くか / どこで使うか

ネットワークの構成を決める場面では、通信をどこで受け、どこへ流し、どう切り替えるかを選ぶ。サービス名だけ覚えても、速くしたい、止まらないようにしたい、社内だけに閉じたい、といった要件には当てはめられない。

## 前提となる知識

| 用語 | 一言の説明 |
|---|---|
| IP・CIDR・ルーティング | アドレスの範囲と経路の基礎（[[VPC の前提知識]]）。 |
| DNS | 名前から、どの IP に案内するかを決める仕組み。 |
| L4（TCP） | 接続の単位で振り分ける層（[[ロードバランサの使い分け]]）。 |
| L7（HTTP） | リクエストの中身で振り分ける層（[[ロードバランサの使い分け]]）。 |

## 本体の解説

### 1. 3つの軸で分ける

| 軸 | 問い | 代表的なサービス |
|---|---|---|
| 近くで受けて配る | 利用者に近い場所でキャッシュや終端をするか | CloudFront、Global Accelerator |
| 名前から振り分ける | どの IP に案内するか（DNS） | Route 53 |
| 中で流す | VPC や拠点の間をどう経路でつなぐか | Transit Gateway、Direct Connect、VPN、PrivateLink |

### 2. CloudFront と Global Accelerator

どちらも利用者に近い場所（エッジ）から AWS に入る。違いは中身を見るかどうか。

CloudFront は HTTP と HTTPS を扱い、コンテンツをエッジに保存（キャッシュ）する。静的な画像や動画に強い。S3 を配信元にするときは、OAC（Origin Access Control）を使う。これで S3 を直接公開せず、CloudFront 経由だけに絞れる。

Global Accelerator は固定の IP を2つ（anycast）持つ。TCP と UDP を、AWS のネットワーク内で目的地まで運ぶ。キャッシュはしない。ゲームや IoT の UDP、固定 IP を顧客に教える必要がある場合に向く。リージョンをまたぐ障害切り替えを速くしたいときも候補になる。

### 3. Route 53 のルーティングポリシー

DNS の答えを、条件によって変える仕組み。要件に書かれた条件（割合、遅延、障害、地域）に合うポリシーを選ぶ。

| ポリシー | 向く場面 |
|---|---|
| シンプル | 1つの宛先だけのとき |
| 加重 | 割合で分けたいとき（カナリアリリースや移行の段階的切り替え） |
| レイテンシー | 利用者に一番近いリージョンへ送りたいとき |
| フェイルオーバー | 障害時にだけ待機系へ切り替えたいとき（ヘルスチェックと組み合わせる） |
| 地理的な場所 | 国や地域で分けたいとき（法令やライセンス） |

エイリアスレコードは、ELB や CloudFront などの AWS リソースを名前で指す、Route 53 独自のレコード。

頂点（example.com そのもの）には CNAME を置けない。CNAME は「この名前は別の名前の別名だ」という記録で、その名前には他の記録を置けないというルールがある。一方、頂点には SOA と NS の記録が必ずあるので、CNAME を置くとこのルールと衝突する。

エイリアスレコードは CNAME と違い、Route 53 が問い合わせに応じて宛先の IP を返す仕組みなので、頂点にも置ける。`example.com` を CloudFront に向けるならエイリアス、`www.example.com` なら CNAME でも足りる。

### 4. 中で流す手段

Transit Gateway は VPC や VPN、Direct Connect をつなぐ中継のハブ。アタッチしたもの同士をハブ経由でつなぐので推移的（中継できる）で、ルートテーブルで流す先を分ける。VPC が増えるほど効く。

Direct Connect は専用線なので、帯域と遅延が安定する。ただし暗号化は標準では無いので、暗号化が要るなら VPN を重ねるか、別の仕組みで暗号化する。冗長化は回線もロケーションも二重にする。

Site-to-Site VPN は、インターネットの上に暗号化されたトンネルを作る。速く安く作れるが、帯域と遅延は回線に依存する。トンネルは2本張って冗長化するのが基本。

PrivateLink は経路を流さず、特定のサービスだけを公開する。相手の VPC と CIDR が重なっていても使える。

### 5. 選び方の順番

1. 利用者に近い場所で受けたい → CloudFront（HTTP）か Global Accelerator（TCP・UDP、固定 IP）
2. どの宛先へ案内するか → Route 53 のルーティングポリシー
3. 拠点や VPC をつなぐ → 数が多ければ Transit Gateway、少なければピアリング
4. 帯域と遅延の安定が要る → Direct Connect。急ぎで安く → VPN
5. 特定のサービスだけ見せる → PrivateLink

### 6. データ転送のコスト

AWS のデータ転送では、インターネットからの受信は無料で、外への送信に料金がかかる。同じリージョンの AZ をまたぐ転送には、送り側と受け側の両方に料金がかかる。NAT ゲートウェイや Transit Gateway を通した処理にも、通した量に応じた料金がかかる。構成を決めるときは、データがどの経路を通るかを先に確認する。

| サービス | 料金の項目 | 補足 |
|---|---|---|
| CloudFront | 利用者へ配信するデータ転送料金 | AWS のオリジンからの取得は無料。オリジン側のリクエスト料金は別 |
| ゲートウェイエンドポイント | 追加料金なし | S3 と DynamoDB 向けの、VPC 内から使う閉じた経路 |
| インターフェースエンドポイント | AZ ごとの時間課金と、流した GB 課金 | PrivateLink を使う接続点 |
| NAT ゲートウェイ | 設置時間の課金と、通したデータ量の課金 | プライベートサブネットから外部へ出る変換装置 |
| Transit Gateway | アタッチ時間の課金と、流したデータ量の課金 | VPC などを集約する中継点 |

CloudFront では、利用者までの配信に CloudFront のデータ転送料金がかかる。AWS のオリジン（S3、EC2、ELB など）から CloudFront への転送には、料金がかからない。オリジン側でかかるのは、S3 の GET のようなリクエスト料金である。AWS の外にオリジンを置くなら、自社側の転送料金も乗る。Origin Shield（オリジン手前のキャッシュ層）を挟むと、オリジンへのリクエスト数を減らせる。ただし Shield 自体の料金が加わる。

AZ（アベイラビリティゾーン）をまたぐ EC2 どうしの転送には、双方向に $0.01/GB の料金がかかる。同じ AZ 内でも、パブリック IPv4 や Elastic IP 宛ての通信には $0.01/GB かかる。プライベート IP を使う EC2、RDS、ElastiCache の間の通信は無料で、IPv6 も同じ VPC 内なら無料になる。別の VPC 宛ては有料だ。

同じリージョンの S3、DynamoDB、SQS、SNS、Kinesis などと EC2 の間の転送も、AZ に関係なく無料である。ただし無料になるのは転送料金だけで、プライベートサブネットから NAT ゲートウェイやインターフェースエンドポイントを通せば、流した量に応じた処理料がかかる。S3 と DynamoDB はゲートウェイエンドポイントを通せば、転送料金も処理料もかからない。AZ を分ける構成は、可用性と引き換えに転送費が増える。

S3 のクロスリージョンレプリケーションには、リージョン間の転送とレプリケーションのリクエストの料金がかかる。Bedrock のクロスリージョン推論は別リージョンで処理されるが、追加の転送料金はかからず、呼び出し元のリージョンの価格で課金される。変わるのはデータの所在地と、データ所在地の要件の扱いである。

## 具体例・コード

グローバル向けの Web サービスの例。

1. 静的な画像は S3 に置き、CloudFront（OAC）で配信する
2. 動的な API は ALB の背後に置き、CloudFront の別のオリジンにする
3. 独自ドメインは Route 53 のエイリアスレコードで CloudFront に向ける
4. 障害時に別リージョンへ切り替えたいなら、CloudFront のオリジングループ（オリジンフェイルオーバー）で別リージョンのオリジンへ切り替える。CloudFront を通さないなら、Route 53 のフェイルオーバーで、オリジンのホスト名のレコードを切り替える

## つまずきポイント

- 「Global Accelerator もキャッシュする」は間違い。キャッシュはしない。
- 「Direct Connect を使えば暗号化もされる」は間違い。標準では暗号化されない。
- 「ゾーンの頂点に CNAME を置ける」は間違い。置けないので、エイリアスレコードを使う。
- 「Route 53 の加重は、障害切り替えの仕組みだ」は間違い。障害時の切り替えはフェイルオーバーで、加重は割合の制御。
- 「PrivateLink は、ピアリングの代わりにいつでも使える」は間違い。経路を流すものではないので、通信の向きと用途が違う。
- 「受信は無料だから転送費は考えなくてよい」は間違い。無料なのはインターネットからの受信だけで、AZ 間の転送や NAT・Transit Gateway の処理料は向きを問わずかかる。AZ を分けて可用性を上げるほど転送費も増える。ゲートウェイエンドポイントだけは、S3 と DynamoDB 向けに追加料金がかからず、インターフェースエンドポイントとは課金の仕組みが別である。
