# ロードバランサの使い分け

## ひとことで

ALB は HTTP を理解して振り分け、NLB は TCP を高速に流し、GWLB は通信を機器に透過的に通す。

## なぜ効くか / どこで使うか

受け口をどこに置くかで、できることと遅延が変わる。HTTP のルーティングが要るのか、固定 IP が要るのか、既存のファイアウォールを通したいのかで、選ぶロードバランサが変わる。

PrivateLink でサービスを公開するには NLB か GWLB が必要、といった組み合わせの制約もある。構成を決める前に押さえておく。

## 前提となる知識

IP・CIDR と DNS の基礎は [[VPC の前提知識]] にある。

| 用語 | 一言の説明 |
|---|---|
| L4 と L7 | どこまで通信の中身を見るかを示す層の区分。 |
| TCP と UDP | 通信の方式の区分。NLB は両方を扱う。 |
| TLS の終端 | 暗号化された通信をロードバランサで復号する処理。 |
| ヘルスチェック | 正常でないターゲットを振り分け先から外す仕組み。 |

## 本体の解説

3種類を層で並べる。下段は GWLB が通信を機器に通す流れ。

![[assets/web/aws-lb-types.svg]]

### 1. 3種類の性格

| 種類 | 層 | 主な用途 | 特徴 |
|---|---|---|---|
| ALB | L7 | HTTP/HTTPS の Web サービス | パスやホスト名での振り分け、WAF、認証、固定レスポンス |
| NLB | L4 | TCP/UDP、低遅延、固定 IP | 低遅延、AZ ごとの固定 IP（Elastic IP も可）、TLS 終端 |
| GWLB | L3 | ファイアウォールなど機器への透過的な経路 | GENEVE でのカプセル化と転送 |

CLB（Classic）は旧世代で、新規の構成では選ばない。

### 2. ALB

HTTP を理解するので、URL のパスやホスト名でターゲットを分けられる。TLS を終端して、認証や WAF を挟むのもここになる。

ターゲットにはインスタンス、IP、Lambda を指定できる。コンテナや EKS では IP ターゲットが基本になる。

### 3. NLB

TCP と UDP をそのまま流す。レイテンシが小さく、IP アドレスが固定になるのが ALB との大きな違いになる。NLB は AZ ごとに1つずつ IP を持ち、そこに自分の Elastic IP を割り当てることもできる。取引先にファイアウォールで許可する IP を伝える、といった場面で効く。

TLS を終端することも、そのまま通すこともできる。PrivateLink でサービスを公開するときは、エンドポイントサービスに NLB を関連付ける。

### 4. GWLB

GWLB は、通信をいったん機器（セキュリティアプライアンス）に通してから届ける。透過的に検査したいときに使う。

GWLB エンドポイントという受け口をサブネットに作り、ルートテーブルでそのエンドポイントへ通信を向ける。通信は GENEVE（UDP 6081）でカプセル化される。

「他社製のファイアウォールを挟みたい」「既存のアプライアンスを活かしたい」という要件が挙がったら、GWLB を選ぶ。セキュリティグループやネットワーク ACL では、要件を満たせない。

### 5. 選び方

1. HTTP の中身で振り分けたいか。はいなら ALB
2. UDP を扱うか、固定 IP が要るか、極端に低遅延か。はいなら NLB
3. 既存のアプライアンスに通信を通したいか。はいなら GWLB

この順で聞くと、たいてい1つに決まる。

## 具体例・コード

複数 VPC の通信を、中央の VPC に置いたファイアウォールで検査する構成を組む。

1. 中央 VPC にファイアウォール（GWLB のターゲット）を置く
2. GWLB を作り、ファイアウォールをターゲットに登録する
3. GWLB をエンドポイントサービスとして公開する（PrivateLink の仕組み）
4. 各 VPC のサブネットに、そのエンドポイントサービスへの GWLB エンドポイントを作る
5. 各 VPC のルートテーブルで、検査したい通信を GWLB エンドポイントへ向ける
6. 戻りの通信も同じ GWLB エンドポイントを通るように経路を書く。行きと帰りで経路がずれると、ファイアウォールが通信を落とす

## つまずきポイント

- 「ALB で UDP を扱える」は間違い。ALB は HTTP/HTTPS 専用。
- 「NLB でパスごとに振り分けられる」は間違い。NLB は L4 なので URL が見えない。
- 「GWLB は通常のロードバランサだ」は間違い。主目的は負荷分散ではなく、機器への透過的な転送。
- 「エンドポイントサービスに ALB を直接つなげる」は間違い。つなげるのは NLB か GWLB で、ALB を使いたいときは NLB のターゲットに ALB を登録する。
- 「ヘルスチェックは緩くしても影響しない」は間違い。緩くすると、異常なターゲットに流し続ける。
- 「行きの経路だけ書けば検査できる」は間違い。行きと帰りで経路がずれると、ファイアウォールが通信を落とす。
