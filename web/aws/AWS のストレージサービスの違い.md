# AWS のストレージサービスの違い

## ひとことで

データを「オブジェクト」「ブロック」「ファイル」のどれで見せたいかで、サービスがほぼ決まる。

## なぜ効くか / どこで使うか

分野1（設計と実装）の設問は、ほぼ「どのストレージを選ぶか」の判断になる。見せ方、共有の範囲、耐久性、コストの4つで切ると、消去法で1つに絞れる。

## 前提となる知識

ブロック、ファイル、オブジェクトの違いが分かればよい。

- ブロック: ディスクの生の領域。OS がファイルシステムを作って使う。
- ファイル: 階層のあるフォルダとファイル。NFS や SMB で共有する。
- オブジェクト: 名前（キー）と中身の組。フォルダの階層はない。HTTP で出し入れする。

## 本体の解説

### 1. 見せ方で分ける

| 見せ方 | サービス | 一言で |
| --- | --- | --- |
| オブジェクト | S3 | HTTP で出し入れする保管庫 |
| ブロック | EBS | EC2 に付ける仮想ディスク |
| ファイル | EFS（Linux）、FSx（Windows など） | 複数の EC2 で同じフォルダを開く |

### 2. S3（オブジェクトストレージ）

S3 は容量の上限をほぼ気にせず使える。データはリージョン内の複数 AZ に保存され、耐久性は 99.999999999%（年間のオブジェクト損失確率は 0.000000001%）とされている。これは壊れない保証ではなく、設計で目指す数字で、可用性（今すぐ読めるか）とは別の指標になる。

ストレージクラスで料金と取り出しやすさを変える。

- Standard: 頻繁に読む。
- Intelligent-Tiering: アクセスが読めないとき、自動で安い層へ動かす。
- Standard-IA / One Zone-IA: たまにしか読まない。最低保存期間と取り出し料金がある。One Zone-IA は1つの AZ だけなので、耐久性は下がる。
- Glacier 系: 長期保管。取り出しに時間がかかるものがある。Deep Archive が最も安いが、取り出しに数時間かかる。

S3 はマウントして OS のディスクにはできない（ファイルとしては使えない）。EC2 のドライブとして付けたい、という要件なら EBS か EFS になる。

### 3. EBS（ブロックストレージ）

EBS は EC2 に付ける仮想ディスクで、1つのボリュームは1つの AZ に属する。別の AZ の EC2 には付けられない（別 AZ へは、スナップショットから作り直す）。

- 1台の EC2 からしか使わないのが基本。io1/io2 だけ、同じ AZ 内の複数 EC2 に付ける Multi-Attach が使える。
- スナップショットは S3 に差分で保存され、別リージョンへのコピーもできる。バックアップの基本になる。
- gp3 が汎用。IOPS を大きく必要とするなら io2。大きなデータを安く順次読むなら st1 や sc1（HDD 系）。

インスタンスストアは EC2 のホストに直付けされた一時ディスク。EC2 を停止すると中身が消えるので、データの保管場所にしてはいけない。その代わり速い。

### 4. EFS（ファイルストレージ）

EFS は NFS でマウントする共有ファイルシステム。複数の EC2 が、複数の AZ から同じフォルダを開ける。容量は自動で増減し、使った分だけ払う。

Linux 向け。Windows の SMB を使うなら FSx for Windows File Server になる。EBS より GB あたりの単価は高い。

### 5. FSx（用途別の共有ファイル）

FSx は、特定のファイルシステムをマネージドで提供する。

- FSx for Windows File Server: SMB、Active Directory と連携。Windows のファイル共有ならこれ。
- FSx for Lustre: 高速な並列処理、機械学習や HPC。S3 と連携できる。
- FSx for NetApp ONTAP、FSx for OpenZFS: 既存の NetApp や ZFS の機能をそのまま使いたいとき。

### 6. Storage Gateway（オンプレとの橋渡し）

オンプレの既存の仕組みを残したまま、裏側を AWS に置く。

- File Gateway: NFS や SMB で見せて、中身を S3 に置く。
- Volume Gateway: iSCSI のディスクとして見せる。キャッシュ型と保管型がある。
- Tape Gateway: 既存のテープ運用を、仮想テープにして S3 や Glacier に置く。

### 7. 移動と複製

- DataSync: ネットワーク経由で、NFS や SMB から S3・EFS・FSx へ自動で運ぶ。
- Snow ファミリー: 回線が細いときに、物理デバイスで大量のデータを運ぶ。
- AWS Backup: 複数サービスのバックアップを、ポリシーで一元管理する。

## 具体例・コード

設問の読み方の例。

1. 「Windows のサーバーからアクセスしたいファイル共有」→ SMB と AD が出た時点で FSx for Windows
2. 「100台の Linux から同じフォルダを読む」→ 複数 EC2 の共有で、Linux なので EFS
3. 「ブートディスクのデータを残して、EC2 を再起動したい」→ EBS（インスタンスストアは消える）
4. 「写真の長期保管、取り出しは数日後でよい」→ S3 Glacier 系で、取り出しの時間と単価を見る

## つまずきポイント

- S3 を EC2 のドライブとして使えると思う。マウントはできず、オブジェクトとして出し入れする。
- EBS は複数 AZ で共有できると思う。1 ボリュームは1 AZ。別 AZ にはスナップショットから作り直す。
- インスタンスストアは停止しても残ると思う。停止や終了で消える。
- One Zone-IA を、耐久性を下げずに安くできると思う。1 AZ 分の耐久性しかない。
- EFS を Windows で使えると思う。SMB が必要なら FSx for Windows。
