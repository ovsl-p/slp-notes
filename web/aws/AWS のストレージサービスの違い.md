# AWS のストレージサービスの違い

## ひとことで

データを「オブジェクト」「ブロック」「ファイル」のどれで見せたいかで、サービスがほぼ決まる。

## なぜ効くか / どこで使うか

分野1（設計と実装）の設問は、ほぼ「どのストレージを選ぶか」の判断になる。見せ方、共有の範囲、耐久性、コストの4つで切ると、消去法で1つに絞れる。

## 前提となる知識

ブロック、ファイル、オブジェクトの違いが分かればよい。

- ブロック: ディスクの生の領域。OS がファイルシステムを作って使う。
- ファイル: 階層のあるフォルダとファイル。NFS や SMB で共有する。
- オブジェクト: 名前（キー）と中身の組。フォルダの階層はない。HTTP で出し入れする。

## 本体の解説

### 1. 見せ方で分ける

| 見せ方 | サービス | 一言で |
| --- | --- | --- |
| オブジェクト | S3 | HTTP で出し入れする保管庫 |
| ブロック | EBS | EC2 に付ける仮想ディスク |
| ファイル | EFS（Linux）、FSx（Windows など） | 複数の EC2 で同じフォルダを開く |

### 2. S3（オブジェクトストレージ）

S3 は容量の上限をほぼ気にせず使える。データはリージョン内の複数 AZ に保存され、耐久性は 99.999999999%（年間のオブジェクト損失確率は 0.000000001%）とされている。これは壊れない保証ではなく、設計で目指す数字で、可用性（今すぐ読めるか）とは別の指標になる。

ストレージクラスで料金と取り出しやすさを変える。

- Standard: 頻繁に読む。
- Intelligent-Tiering: アクセスが読めないとき、自動で安い層へ動かす。
- Standard-IA / One Zone-IA: たまにしか読まない。最低保存期間と取り出し料金がある。One Zone-IA も設計上の耐久性は Standard-IA と同じ 99.999999999% だが、1つの AZ にしか置かないので、その AZ が失われるとデータも失われる（可用性は 99.5%）。
- Glacier 系: 長期保管。取り出しに時間がかかるものがある。Deep Archive が最も安いが、取り出しに数時間かかる。

Mountpoint for Amazon S3 を使えば、バケットを Linux のファイルシステムとしてマウントできる。ただし既存のファイルを書き換えたりディレクトリを消したりはできず、ブロックデバイスにもならない。汎用のドライブとして付けたいなら EBS が要る。

### 3. EBS（ブロックストレージ）

EBS は EC2 に付ける仮想ディスクで、1つのボリュームは1つの AZ に属する。別の AZ の EC2 には付けられない（別 AZ へは、スナップショットから作り直す）。

- 1台の EC2 からしか使わないのが基本。io1/io2 だけ、同じ AZ 内の複数 EC2 に付ける Multi-Attach が使える。
- スナップショットは S3 に差分で保存され、別リージョンへのコピーもできる。バックアップの基本になる。
- gp3 が汎用。IOPS を大きく必要とするなら io2。大きなデータを安く順次読むなら st1 や sc1（HDD 系）。

インスタンスストアは EC2 のホストに直付けされた一時ディスク。再起動では中身が残り、停止・休止・終了で消える。データの保管場所にしてはいけない。その代わり速い。

### 4. EFS（ファイルストレージ）

EFS は NFS でマウントする共有ファイルシステム。複数の EC2 が、複数の AZ から同じフォルダを開ける。容量は自動で増減し、使った分だけ払う。

Linux 向け。Windows の SMB を使うなら FSx for Windows File Server になる。EBS より GB あたりの単価は高い。

### 5. FSx（用途別の共有ファイル）

FSx は、特定のファイルシステムをマネージドで提供する。

- FSx for Windows File Server: SMB、Active Directory と連携。Windows のファイル共有ならこれ。
- FSx for Lustre: 高速な並列処理、機械学習や HPC。S3 と連携できる。
- FSx for NetApp ONTAP、FSx for OpenZFS: 既存の NetApp や ZFS の機能をそのまま使いたいとき。

### 6. Storage Gateway（オンプレとの橋渡し）

オンプレの既存の仕組みを残したまま、裏側を AWS に置く。

- File Gateway: NFS や SMB で見せて、中身を S3 に置く。
- Volume Gateway: iSCSI のディスクとして見せる。キャッシュ型と保管型がある。
- Tape Gateway: 既存のテープ運用を、仮想テープにして S3 や Glacier に置く。

### 7. 移動と複製

3つは目的が違う。どれも「データを別の場所に置く」点で似ているので、混同しやすい。

DataSync は、オンプレに置いたエージェントから NFS や SMB のデータを S3・EFS・FSx へネットワーク越しに運ぶ。変更分だけを運ぶ増分転送と、スケジュール実行ができる。移行の途中で、本番を動かしたまま同期し続けるときに向く。転送後にデータを照合する機能もある。上限は回線の帯域になる。

Snow ファミリーは、データを専用のデバイスに詰めて AWS に郵送する。回線で送ると時間がかかりすぎる量を、一度に運ぶときに使う。判断は計算で行う。100 TB を 1 Gbps の回線で送ると約9日かかるので、その時間と郵送の時間を比べる。デバイスは容量やエッジでの計算の要否で種類が分かれる。ただし Snowball Edge は 2025年11月7日から新規の顧客には提供しておらず、新しい案件では、オンラインは DataSync、物理媒体の持ち込みは AWS Data Transfer Terminal が案内されている。試験の選択肢としては残るので、仕組みとして覚えておく。

AWS Backup は、EBS、EFS、RDS、DynamoDB、FSx などのバックアップを、スケジュールと保持期間のルールで一元管理する。組織の複数アカウントに同じ方針を当てられる。Vault Lock を使うと、一定期間は誰も消せないようにできる。移行の道具ではなく、障害や誤削除から戻すための道具になる。

試験での見分け方は、次のとおり。

- 今の環境を移したい、移行中も同期したい → DataSync
- 回線では間に合わないほど大量を、一度に運びたい → Snow
- 定期的に取って、一定期間保持して、戻せるようにしたい → AWS Backup

DataSync はバックアップの世代を管理しない。AWS Backup は移行の転送には使わない。Snow は運ぶだけで、定期的な保護は別に考える。

### 8. ストレージのコストを下げる

ストレージの費用は、データの使われ方に合わせて安い層へ移すことで下げられる。S3（オブジェクトを保存する AWS の領域）のライフサイクルポリシーは、時間がたったオブジェクトを安いクラスへ自動で移す仕組みだ。ただし、取り出しに料金がかかるクラスや最低保存期間があるクラスがあり、移す前に確認が要る。

アクセス頻度が読めないデータには S3 Intelligent-Tiering が向く。監視の料金がかかり、小さいオブジェクトが多いと割高になりうる。

EBS（EC2 に付ける仮想ディスク）では gp3 が gp2 より GiB あたりの単価が20%安い。gp3 は容量と性能を切り離して設定でき、3,000 IOPS（1秒あたりの読み書き回数）と 125 MiB/s はストレージの料金に含まれる。EBS のスナップショットは増分で、変わった部分だけが保存される。

EFS にもライフサイクルがあり、使われないファイルを安いストレージクラスへ移せる。バックアップは AWS Backup で保持期間を決め、Data Lifecycle Manager でスナップショットの作成と削除を自動化する。

## 具体例・コード

設問の読み方の例。

1. 「Windows のサーバーからアクセスしたいファイル共有」→ SMB と AD が出た時点で FSx for Windows
2. 「100台の Linux から同じフォルダを読む」→ 複数 EC2 の共有で、Linux なので EFS
3. 「ブートディスクのデータを残して、EC2 を停止して再開したい」→ EBS（インスタンスストアは停止で消える）
4. 「写真の長期保管、取り出しは数日後でよい」→ S3 Glacier 系で、取り出しの時間と単価を見る

## つまずきポイント

- S3 を EC2 の汎用ドライブとして使えると思う。Mountpoint でマウントはできるが、既存ファイルの書き換えはできず、ブロックデバイスでもない。
- EBS は複数 AZ で共有できると思う。1 ボリュームは1 AZ。別 AZ にはスナップショットから作り直す。
- インスタンスストアは停止しても残ると思う。停止や休止、終了で消える。
- One Zone-IA を、Standard-IA より壊れやすいと思う。設計上の耐久性の数字は同じで、AZ が失われると読めなくなる点が違う。
- EFS を Windows で使えると思う。SMB が必要なら FSx for Windows。

- 「gp3 の IOPS を上げるには、容量を増やす必要がある」は間違い。gp3 は容量と性能を切り離して設定でき、3,000 IOPS と 125 MiB/s まではストレージ料金に含まれる。
- 「EBS のスナップショットは毎回すべてのデータを保存する」は間違い。増分で、前回から変わった部分だけを保存する。
