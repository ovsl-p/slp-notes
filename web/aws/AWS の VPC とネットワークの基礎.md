# AWS の VPC とネットワークの基礎

## ひとことで

VPC はリージョン内に切った仮想ネットワークで、通信できるかどうかはルートテーブルとセキュリティグループの2段で決まる。

## なぜ効くか / どこで使うか

AWS の設計問題は、ほぼ全部ネットワークの上で起きる。サブネットの切り方、経路の通し方、外部から届くかどうかは、この基礎が分かっていないと判断できない。

コンテナや Kubernetes を使う場合も、Pod が載るネットワークはこの VPC なので、ここが曖昧だと Service や Ingress の話が呑み込めない。

## 前提となる知識

| 知っておくこと | なぜ必要か |
| --- | --- |
| IP アドレスと CIDR | VPC とサブネットは CIDR で切る。重複すると接続できない |
| ルーティング | 「どこ宛のパケットをどこへ送るか」の表。VPC の要 |
| NAT の考え方 | プライベートな IP のまま外に出る仕組み |
| DNS の基礎 | VPC の中にも名前解決の仕組みがある（[[AWS の DNS と名前解決]]） |

## 本体の解説

### 1. VPC とサブネット

VPC はリージョン内に1つ以上の CIDR ブロックで作る仮想ネットワークで、その中をサブネットで区切る。

サブネットは AZ に紐づく。1つのサブネットが複数の AZ にまたがることはないので、冗長化するなら AZ の数だけサブネットを作る。

パブリックとプライベートの違いは名前ではなく経路で決まる。サブネットのルートテーブルにインターネットゲートウェイへの経路があればパブリックで、なければプライベートになる。

### 2. ルートテーブル

ルートテーブルはサブネットに関連付ける。行は「宛先 CIDR」と「ターゲット（IGW、NAT ゲートウェイ、Transit Gateway、VPC ピアリングなど）」の組になる。

VPC 内の通信はローカルルートで自動的に通る。それ以外の宛先は、明示的に足さないと通らない。逆に言えば、足し忘れが「つながらない」の大半になる。

同じ VPC の中でも、サブネットごとに別のルートテーブルを当てられる。片方のサブネットだけ外部に出せる、という設計はここで作る。

### 3. 外に出るための装置

| 装置 | 役割 | 置き場所 |
| --- | --- | --- |
| インターネットゲートウェイ | パブリックサブネットと外部をつなぐ | VPC に1つ |
| NAT ゲートウェイ | プライベートな IP のまま外へ出る（送信元は NAT の IP） | パブリックサブネット、AZ ごと |
| VPC エンドポイント | AWS のサービスへ、インターネットを経由せずに届く | サブネット内（インターフェイス型） |

NAT ゲートウェイは AZ ごとに置く。1つだけ置くと、その AZ が落ちたときに他の AZ からの通信も止まる。

VPC エンドポイントには2種類ある。ゲートウェイ型は S3 と DynamoDB 向けで、ルートテーブルに経路を足す形になる。インターフェイス型は ENI を作る形で、セキュリティグループが効く。PrivateLink はこのインターフェイス型の仕組みを使っている。

### 4. 通信を絞る2段

セキュリティグループはインスタンス（ENI）単位で、ステートフル（戻りの通信は自動で許可）で、許可ルールしか書けない。

ネットワーク ACL はサブネット単位で、ステートレス（戻りも明示的に許可する）で、拒否ルールも書ける。

実務では、拒否はネットワーク ACL、細かい許可はセキュリティグループ、という分担になる。ACL は番号順に評価されるので、順序を間違えると後ろのルールが効かない。

### 5. DNS と VPC

VPC には CIDR の先頭 +2 のアドレスに Route 53 Resolver がいる。＋1 はルーター用なので、DNS ではない。この +2 は VPC の中からしか使えない。

詳細は [[AWS の DNS と名前解決]] に分けた。

### 6. 料金で効くところ

NAT ゲートウェイは時間課金と処理量課金が乗る。AZ を跨いだ通信にもデータ転送料金がかかる。

設計問題で「最もコスト効率よく」とあったら、NAT を減らせる構成（エンドポイント経由にする、AZ を跨がない）を疑う。

## 具体例・コード

最小の構成を頭の中で組み立てるときの順番。

1. VPC の CIDR を決める（例: 10.0.0.0/16）
2. AZ の数だけパブリックとプライベートのサブネットを切る（例: /24 ずつ）
3. パブリック側のルートテーブルに `0.0.0.0/0 → IGW` を入れる
4. プライベート側に `0.0.0.0/0 → NAT ゲートウェイ` を入れる
5. セキュリティグループで、必要なポートだけ許可する

## つまずきポイント

- サブネットを「パブリックサブネット」という名前で作っただけで外部に出られると思う。決めているのはルートテーブル。
- ネットワーク ACL をステートフルだと思う。戻りの通信も明示的に許可しないと落ちる。
- NAT ゲートウェイを1つだけ置いて冗長化したつもりになる。AZ 障害で止まる。
- CIDR が重複した VPC 同士をつなごうとする。ピアリングでは重複が許されない。
- エンドポイントを「タダで速くなるもの」と思う。インターフェイス型は ENI と時間課金が発生する。
