# AWS の DNS と名前解決

## ひとことで

VPC の中の名前解決は Route 53 Resolver が担い、外の DNS とつなぐときはエンドポイントの向きで使う道具が変わる。

## なぜ効くか / どこで使うか

ハイブリッド構成でもマルチアカウントでも、最初に詰まるのは名前解決になる。IP は通っているのに名前が引けない、という状態はここを読めば解ける。

オンプレの社内ドメインを AWS から引きたい、AWS の名前をオンプレから引きたい、別アカウントのゾーンを共有したい、という3つの要求で使う仕組みが違う。

## 前提となる知識

| 知っておくこと | なぜ必要か |
| --- | --- |
| DNS の仕組み | 権威サーバと再帰サーバの役割分担が、そのまま AWS の構成に対応する |
| 転送（フォワーディング） | 「このドメインはこの DNS に聞く」という振り分け |
| VPC の CIDR | Resolver のアドレスが CIDR の +2 に決まっている |
| パブリックとプライベートの違い | 社内の名前を公開してしまう事故を防ぐ |

## 本体の解説

### 1. VPC の中の Resolver

VPC には Route 53 Resolver が用意されていて、CIDR の先頭 +2 のアドレスにいる（+1 はルーター）。169.254.169.253 でも同じものに届く。

VPC の DNS 属性は2つあり、役割が違う。

| 属性 | 役割 | 無効だと |
| --- | --- | --- |
| enableDnsSupport | VPC で AWS の DNS を使えるようにする | 名前解決そのものができない |
| enableDnsHostnames | パブリック IP を持つインスタンスにパブリック DNS 名を付ける | 名前が付かない |

プライベートホストゾーンを使うには、両方を true にする必要がある。enableDnsHostnames はデフォルト VPC 以外では最初 false なので、自分で作った VPC ではここでつまずく。

### 2. プライベートホストゾーン

Route 53 のプライベートホストゾーンは、VPC に関連付けることでその VPC から引けるようになる。関連付いていない VPC からは引けない。

別アカウントの VPC で使いたいときは2段階になる。ゾーン側で VPC の関連付けを承認し、VPC 側で関連付ける。逆にすると「関連付けたのに引けない」になる。

同じゾーンを複数の VPC で使いたいだけなら、RAM で共有する方法もある。

### 3. オンプレとつなぐ向き

ここが一番混同しやすい。エンドポイントは向きで決まる。

| やりたいこと | 使うもの |
| --- | --- |
| VPC からオンプレの社内ドメインを引きたい | アウトバウンドエンドポイント＋転送ルール |
| オンプレから AWS のプライベート名を引きたい | インバウンドエンドポイント |
| 両方向に引きたい | 両方を作る |

アウトバウンドは「AWS から外へ問い合わせる出口」で、転送ルールにドメインと転送先 DNS を書く。インバウンドは「外から AWS 内の Resolver に入る入口」になる。

DHCP オプションセットを書き換えてオンプレ DNS に向ける方法は、VPC 内の名前解決を全部変えてしまうので、通常は選ばない。

### 4. Resolver ルールの共有

転送ルールは VPC に関連付けて使う。多数の VPC で同じルールを使うなら、RAM で共有して各 VPC に関連付ける。

中央のネットワークアカウントにエンドポイントを置き、他のアカウントの VPC から共有する形が定番になる。

## 具体例・コード

オンプレの `corp.example.com` を VPC から引く場合。

1. アウトバウンドエンドポイントを、VPC の2つの AZ のサブネットに作る
2. 転送ルールを作り、`corp.example.com` の転送先にオンプレの DNS の IP を書く
3. ルールを対象の VPC に関連付ける
4. セキュリティグループと、オンプレ側のファイアウォールで DNS（UDP/TCP 53）を通す

## つまずきポイント

- インバウンドとアウトバウンドの向きを逆に覚える。名前の向きは「AWS に入る／AWS から出る」で、名前解決の要求の向きとは一致しない。
- プライベートホストゾーンを関連付けただけで引けると思う。DNS 属性が2つとも有効でないと引けない。
- パブリックホストゾーンに社内の名前を置く。インターネットに公開される。
- Resolver の +1 を DNS として指定する。+1 はルーターで、DNS は +2。
- 別アカウントのゾーンを、VPC 側の操作だけで引こうとする。ゾーン側の承認が要る。
