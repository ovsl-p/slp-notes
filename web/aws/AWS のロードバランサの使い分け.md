# AWS のロードバランサの使い分け

## ひとことで

ALB は HTTP を理解して振り分け、NLB は TCP を高速に流し、GWLB は通信を機器に透過的に通す。

## なぜ効くか / どこで使うか

受け口をどこに置くかで、できることと遅延が変わる。HTTP のルーティングが要るのか、固定 IP が要るのか、既存のファイアウォールを通したいのかで選ぶものが変わる。

PrivateLink の前段には NLB が必要、といった組み合わせの制約もここで理解する。

## 前提となる知識

| 知っておくこと | なぜ必要か |
| --- | --- |
| L4 と L7 | どこまで中身を見るかで、できる振り分けが変わる |
| TCP と UDP | NLB は UDP も扱える |
| TLS の終端 | 復号するか、通すかで設計が変わる |
| ヘルスチェック | 正常でないターゲットを外す仕組み |

## 本体の解説

### 1. 3種類の性格

| 種類 | 層 | 主な用途 | 特徴 |
| --- | --- | --- | --- |
| ALB | L7 | HTTP/HTTPS の Web サービス | パスやホスト名で振り分け、WAF、認証、固定レスポンス |
| NLB | L4 | TCP/UDP、低遅延、固定 IP | 超低遅延、Elastic IP を付けられる、TLS 終端も可 |
| GWLB | L3 | ファイアウォールなど機器への透過的な経路 | GENEVE でカプセル化して転送 |

CLB（Classic）は旧世代で、新規設計では選ばない。

### 2. ALB

HTTP を理解するので、URL のパスやホスト名でターゲットを分けられる。TLS を終端して、認証や WAF を挟むのもここになる。

ターゲットにはインスタンス、IP、Lambda を指定できる。コンテナや EKS では IP ターゲットが基本になる。

### 3. NLB

TCP と UDP をそのまま流す。レイテンシが小さく、1つの NLB に Elastic IP を付けて固定 IP にできるのが大きな違いになる。

TLS を終端することも、通すこともできる。PrivateLink でサービスを公開するときは、この NLB が前段になる。

### 4. GWLB

GWLB は、通信をいったん機器（セキュリティアプライアンス）に通してから届ける。透過的に検査したいときに使う。

GWLB エンドポイントという受け口をサブネットに作り、ルートテーブルでそのエンドポイントへ通信を向ける。通信は GENEVE（UDP 6081）でカプセル化される。

「他社製のファイアウォールを挟みたい」「既存のアプライアンスを活かしたい」が出たら GWLB を疑う。セキュリティグループやネットワーク ACL では、要件を満たせない。

### 5. 選び方

1. HTTP の中身で振り分けたいか。はいなら ALB
2. UDP を扱うか、固定 IP が要るか、極端に低遅延か。はいなら NLB
3. 既存のアプライアンスに通信を通したいか。はいなら GWLB

この順で聞くと、だいたい1つに決まる。

## 具体例・コード

複数 VPC の通信を、中央の VPC に置いたファイアウォールで検査する構成。

1. 中央 VPC にファイアウォール（GWLB のターゲット）を置く
2. GWLB を作り、ファイアウォールをターゲットに登録する
3. 各 VPC のサブネットに GWLB エンドポイントを作る
4. 各 VPC のルートテーブルで、検査したい宛先を GWLB エンドポイントへ向ける
5. 戻りの経路も同じように通す

## つまずきポイント

- ALB で UDP を扱おうとする。ALB は HTTP/HTTPS 専用になる。
- NLB でパスごとの振り分けをしようとする。L4 なので URL は見えない。
- GWLB を通常のロードバランサだと思う。主目的は負荷分散ではなく、機器への透過的な転送になる。
- PrivateLink の前段に ALB を置く。サービス公開の前段は NLB になる。
- ヘルスチェックを緩くして、異常なターゲットに流し続ける。
