# 監査証拠の提出

## ひとことで

Audit Manager は、自社の AWS の使い方を示す証拠を集める。Artifact は、AWS 基盤を示す証拠を取り出す。

## なぜ効くか / どこで使うか

監査では、規格が求める証拠を毎回手作業で集めると時間がかかる。そこで証拠の収集には Audit Manager と Artifact を使うが、両者は証拠の出どころが違うため、求められる証拠に応じて使い分ける必要がある。

把握しておきたいのは、AWS 基盤の証拠と自社の利用の証拠は別物だという点だ。

## 前提となる知識

| 用語 | 一言の説明 |
|---|---|
| 監査 | 規格どおりに運用されているかを確かめる作業。 |
| 規格（フレームワーク） | 監査の基準となる枠組み。 |
| 管理策（コントロール） | 規格が求める個々の対策項目。 |
| 証拠（エビデンス） | 管理策を満たしていることを示す記録。 |
| 評価（アセスメント） | Audit Manager で証拠を集める対象の単位。 |
| コンプライアンス資料 | 規格への適合を示す文書（レポート）。 |
| 合意書（BAA など） | 顧客と AWS が取り交わす契約文書。 |
| 管理アカウント | 組織配下のアカウントを束ねる親のアカウント。 |
| 設定項目（CI） | Config が記録する、リソースの設定と属性をひとまとめにした記録。 |

## 本体の解説

### 1. Audit Manager の役割

Audit Manager は、評価の対象アカウントを決めると証拠の収集を始める。

自動で集めるのは3種類で、それぞれ出どころが決まっている。コンプライアンスチェックは Security Hub CSPM と Config の評価結果、ユーザー操作は CloudTrail のログ、設定のスナップショットは各サービスの API（describe、get、list など）を呼んだ結果から取る。

自動で集めた情報は証拠に変換され、管理策に紐付けられる。自分でアップロードした証拠（手動証拠）も、管理策に紐付けられる。レポートには、集めた証拠のうち自分で選んだものだけが入る。

### 2. AWS Artifact の役割

Artifact は、AWS 側のコンプライアンス資料と合意書を取り出すポータルである。

取り出せるのは主に、AWS 基盤が規格を満たしていることの証拠になる。Marketplace の ISV が出したレポートも、Vendor Insights でアクセスを許可されていれば見られる。顧客自身の利用の証拠は含まれない。

組織の管理アカウントで合意書を受け入れると、既存と今後のメンバーアカウントすべてに自動で適用される。組織がすべての機能で有効になっていることが前提になる。

### 3. 2つの違い

Artifact は、AWS 基盤が規格を満たしていることを示す。Audit Manager は、自社の AWS の使い方が規格を満たしていることを示す。監査では両方を組み合わせて提出する場面がある。

### 4. 注意点

Audit Manager は 2026年4月30日から、新しいアカウントでセットアップできなくなった。同サービスはメンテナンスモードに入っており、新機能や新しいフレームワークは追加されない。

既存の利用者の扱いは次のとおり。

| 利用形態 | 新しい評価 | アカウントの追加 | リージョンの追加 |
|---|---|---|---|
| 単一アカウント | 作成できる | できない | できない |
| 組織 | 作成できる | 組織内ならできる | できない |

代替として、AWS は Config の適合パック、Control Tower、Security Hub CSPM を挙げている。ただし適合パックは Audit Manager の直接の代替ではない、と AWS 自身が書いている。適合パックが証拠にするのは、Config ルールの評価結果と、その根拠になる設定項目（CI）だけである。CloudTrail のログ、Security Hub CSPM のコントロールの検出結果、対象サービスへの API 呼び出しの結果は集めない。

適合パックには、SOC 2、GDPR、ISO/IEC 27001:2013 などに対応するテンプレートがない。Audit Manager のレポートに相当する監査レポートの出力機能もない。

## 具体例・コード

監査に出すまでの手順は次の6つである。

1. 監査で求められている規格と管理策を確認する
2. 各管理策が AWS 基盤の話か、自社の使い方の話かを切り分ける
3. 基盤の話なら、Artifact で該当のレポートや合意書を取り出す
4. 使い方の話なら、既存の Audit Manager 利用者は評価の対象アカウントを決める。新規に始める場合は、Config の適合パックで技術的な管理策を評価し、足りない証拠は別の手段で補う
5. 証拠が管理策に紐付いているかを確認する
6. レポートに入れる証拠を選び、提出前に内容を確認する

## つまずきポイント

- 「Artifact のレポートがあれば、自社の証拠も足りる」は間違い。Artifact のレポートは基盤の証拠にすぎず、利用の証拠は別に必要になる。
- 「Audit Manager を入れれば規格に準拠する」は間違い。証拠を集めるだけで、準拠しているかの判断は別途必要になる。
- 「組織の管理アカウントで合意すれば、配下の証拠がすべて揃う」は間違い。合意の適用は配下に及ぶが、自社の利用の証拠は含まれない。
- 「Audit Manager は今から誰でも使える」は間違い。2026年4月30日から、新しいアカウントではセットアップできない。
- 「設定のスナップショットがあれば、ユーザー操作の履歴も揃う」は間違い。設定の状態とユーザー操作は別の種類の証拠になる。
- 「Config の適合パックは Audit Manager の直接の代替になる」は間違い。適合パックが証拠にするのは Config ルールの評価結果と設定項目（CI）だけで、CloudTrail のログなどは集めない。
