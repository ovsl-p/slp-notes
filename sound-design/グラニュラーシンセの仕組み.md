# グラニュラーシンセの仕組み

## ひとことで

音を細かい粒に刻んで撒き直し、重ねて新しい音にする合成法。粒の長さと密度が、音程感とノイズ感のバランスを決める。

## なぜ効くか / どこで使うか

- **時間伸縮で音程が変わらない**（粒を撒く間隔だけ変える）。極端に伸ばすとパッド／ドローンになる。
- **原音の質感を保ったまま、リズムと密度だけを変える**。録った声やフィールドレコーディングを素材にできる。
- 粒が短いと「ざらつき・ノイズ的」、長いと「音程が保たれる」。**同じエンジンでテクスチャからメロディまで出る**。
- アンビエント、ドローン、フィルム音響、テクノのグリッチ、パッド、声のピッチシフト（PSOLA 系）まで射程が広い。
- 実装が軽い。FFT 不要、窓掛けと加算だけ。リアルタイムでも数百粒なら余裕。
- 理論的な背景は Gabor の「聴覚の量子」（1947）→ Xenakis → Roads の *Microsound*。音響合成と知覚の境界を扱う手法でもある。

## 前提となる知識

| 知っておくこと | なぜ必要か |
| --- | --- |
| サンプリング定理とサンプルレート | 粒の長さはサンプル数で決まる。44.1kHz なら 1ms = 44.1 サンプル |
| 窓関数（Hann / Tukey / Gaussian） | 粒の両端をゼロにしないとクリックが出る。窓の形が音色と帯域を決める |
| 時間周波数の不確定性 | 短い粒は帯域が広い。粒長を決めることは「音程感かノイズ感か」を決めること |
| エンベロープ | 粒の窓＝エンベロープ。アタック/リリースの理解がそのまま使える |
| 補間（線形・3次） | 再生速度を変えるとサンプル間を飛び越える。補間なしはエイリアスとジッパーノイズ |
| 位相と重ね合わせ | 粒同士が干渉する。位相が揃うと音量が跳ね、打ち消すと「シュワシュワ」になる |
| バッファとブロック処理 | 粒はブロック境界をまたぐ。リングバッファの管理が必要 |
| リアルタイム制約 | オーディオスレッドで確保・解放するとノイズが乗る → [[アロケータの基礎]] |
| 空間音響 | 粒ごとにパン／定位を置くと広がりが出る（粒を空間に散らすのが定番） |

## 本体の解説

### 1. 1粒（グレイン）の構造

粒は4つのパラメータで決まる。

- **位置 (position)**: 素材のどこを読むか
- **長さ (duration)**: 2〜100ms が実用域（1ms 未満はクリック／ノイズ、200ms 超は「切れ端」に聞こえる）
- **窓 (window envelope)**: 両端を0にする包絡。Hann が最も普通
- **再生速度 (rate)**: 1.0 で原音と同じピッチ

```
素材:  ─────────[■■■■]─────────   ← 位置から長さぶん切り出す
窓:    0 ↗ 1 ↘ 0                  ← 端を0にしないと「プチッ」と鳴る
出力:  粒を時間軸に並べて加算する
         ▁▂▅█▅▂▁        ▁▂▅█▅▂▁
       粒1              粒2        粒3 …
```

**窓が必須な理由**: 途中で切り取った波形は端で不連続になる。不連続はクリック（広帯域のインパルス）として聞こえる。矩形窓（＝切りっぱなし）にすると「パチパチ」いうのはこれ。

### 2. パラメータと知覚の対応

| パラメータ | 上げると | 下げると |
| --- | --- | --- |
| 粒長 duration | 音程が保たれる、なめらか | ノイズ的、金属的、帯域が広がる |
| 密度 density (粒/秒) | 連続したテクスチャ | 粒が個別に聞こえる（粒状感） |
| 重なり = 密度 × 粒長 | 滑らか、CPU 増 | 隙間が出てリズミック |
| 位置 scan | 素材を速く進む | 同じ場所を擦り続ける（ドローン） |
| 再生速度 rate | ピッチ上がる・粒が短くなる | ピッチ下がる・粒が長くなる |
| ジッタ | 有機的、定位がぼやける | 機械的、周期的（バズ） |

**重なり (overlap)** が一番効く数字。`密度 × 粒長(秒)` が 1 未満なら粒が離れて聞こえ、2〜4 で滑らか、10 を超えるとほぼ連続音。

### 3. 重ね合わせと位相（COLA）

粒を等間隔で足すと、窓の和が**一定**でないと音量がうねる。Hann 窓は「重なりが 50%（hop = 粒長/2）」のとき、窓の和がちょうど 1.0 で一定になる（**COLA**: constant overlap-add）。手元で実測した値：

| 重なり | 窓の和（定常部） | リップル |
| --- | --- | --- |
| 50%（hop = N/2） | 1.0000 | 0.006 |
| 66.7%（hop = N/3） | 1.5000 | 0.000 |
| 75%（hop = N/4） | 1.9925 | 0.003 |

つまり **Hann は hop ≤ 粒長/2 なら COLA**。この条件を外すと（例: 45% 重なり）窓の和が周期的に脈打ち、**音量のうねり（トレモロ）**として聞こえる。実装では「1/(密度×粒長) で割る」だけでも実用上は足りるが、うねりが耳につくなら **窓の和で正規化**する。

位相の話も同じくらい大事。48kHz で 20ms の粒は 960 サンプル。隣り合う粒の位相が揃うと**コムフィルタ**が立ち、特定の周波数が強調される（金属的な響き）。逆にバラバラだと平均化されて「シュワシュワ」した質感になる。**ジッタ（位置の微小ランダム化）はこの2つの間を調整するつまみ**。

### 4. 時間伸縮とピッチシフトは「別の操作」

混同しやすいが、別物。

- **時間伸縮（ステレッチ）**: 粒を撒く**間隔**を変える。`rate` は 1.0 のまま → 音程は変わらない
- **ピッチシフト**: 粒の**再生速度** `rate` を変える。撒く間隔はそのまま → 音程が変わる
- 両方変えると原音から離れる。`rate` を上げると粒の中の波形が速く進むので、**粒が実質的に短くなり帯域が広がる**（ピッチを上げると音が「細く・明るく」なる理由のひとつ）

### 5. 粒の周期性が「音程」を作る

粒を等間隔で撒くと、**粒の繰り返し周波数が新しい音程として聞こえる**（グラニュラー・バズ／グレイン・トーン）。例: 20ms 間隔（50粒/秒）なら 50Hz の唸りが乗る。

- 周期を素材のピッチと同期させると倍音が揃って「音程のある音」になる（Roads のいう synchronization。PSOLA やボコーダ系の考え方に近い）
- 意図せずバズる場合は **ジッタを入れる**か、密度を上げて周期を聴覚の分解能以下にする（だいたい 100 粒/秒くらいから連続に聞こえ始める）

### 6. 短い粒は帯域が広い（不確定性）

粒長 τ の窓を掛けた正弦波は、周波数軸で **約 1/τ〜2/τ の幅**に広がる。手元で測った -6dB 幅（Hann 窓、220Hz の正弦波）：

| 粒長 τ | 実測 -6dB 幅 | 1/τ |
| --- | --- | --- |
| 2ms | 571Hz | 500Hz |
| 5ms | 355Hz | 200Hz |
| 10ms | 205Hz | 100Hz |
| 20ms | 108Hz | 50Hz |
| 50ms | 43Hz | 20Hz |
| 100ms | 22Hz | 10Hz |

実測は **約 2.1/τ** に漸近する（Hann の主ローブ幅）。つまり 5ms の粒は **1オクターブ以上の帯域**を占める。だから短い粒は「音程がぼやけてノイズ的」になり、100ms まで伸ばすと音程がはっきりする。**粒長つまみは「音程↔ノイズ」のつまみ**でもある。

### 7. 実装方式は3つ

1. **タイムドメイン（サンプル読み出し）**: 一番普通。粒ごとに素材を読んで窓を掛けて足す。軽い。下のコードはこれ
2. **スペクトル（FFT グレイン）**: 周波数領域で粒を作る。柔軟だが重い。位相ボコーダと組み合わせると時間伸縮の質が上がる
3. **ピッチ同期（PSOLA / TD-PSOLA）**: 声のピッチ周期に合わせて粒を置く。声のピッチシフトで定番（粒の位置を「声の1周期」に揃えるのがコツ）

### 8. リアルタイム実装の勘所

- **粒プール（固定配列）**: 事前に最大粒数ぶんの状態を確保し、空きスロットを使い回す。オーディオスレッドで `malloc` しない → [[アロケータの基礎]]
- **粒はブロック境界をまたぐ**: ブロック処理なら「前のブロックから続いている粒」を保持して次のブロックでも書き続ける
- **スケジューラ**: 累積時間（`nextTime += 1/density`）で発火。`for` で回すときは 1ブロック内で複数発火する場合に注意
- **補間**: `rate ≠ 1.0` なら必須。線形で十分なことも多いが、ピッチを大きく動かすなら 3次（Catmull-Rom）やスプライン
- **端の処理**: 素材の終端を超えたら「ループ」「クランプ」「無音」のどれにするかを決める。決めておかないとプツプツ出る
- **正規化**: 密度×粒長で割る or 窓の和で割る。後者が正確

### 9. 音作りのレシピ

- **パッド／アンビエント**: 粒長 50〜150ms、密度 20〜40、scan 0.02〜0.1、左右で位置を僅かにずらす、Hann 窓
- **グリッチ**: 粒長 5〜15ms、密度 10〜30、位置ランダム、矩形／Tukey 窓、ジッタ大きめ
- **ドローン**: 粒長 200ms 以上、密度 5〜10、scan 0（同じ場所を擦る）、フィードバックで厚みを足す
- **粒をリズムに**: 密度をテンポ同期（16分＝その周期で発火）、位置を拍ごとにジャンプ
- **声のピッチシフト**: PSOLA（粒を声の周期に同期）。単純グラニュラーだと「二重声」っぽくなる

## 具体例・コード

純 Python（標準ライブラリのみ）で書いた動くグラニュラーエンジン。**このコードの出力を実際に wav にして確認済み**（下の音声ファイル）。

```python
import math

SR = 44100

def hann(n):
    return [0.5 - 0.5 * math.cos(2 * math.pi * i / (n - 1)) for i in range(n)]

def granular(src, seconds, dur_ms, density, scan=1.0, rate=1.0):
    """src を dur_ms の粒で刻み、density 粒/秒 で撒いて加算する"""
    n = max(2, int(dur_ms / 1000 * SR))      # 粒長（サンプル数）
    win = hann(n)
    total = int(seconds * SR)
    out = [0.0] * (total + n)
    spacing = SR / density                   # 粒を撒く間隔（サンプル）
    limit = len(src) - n - 2
    gain = 1.0 / max(1.0, density * dur_ms / 1000.0)  # 重なりぶん下げる

    t, pos = 0.0, 0.0
    while t < total:
        start = int(t)
        for i in range(n):
            idx = pos + i * rate             # 粒の中の読み出し位置
            if idx >= limit:
                idx %= limit
            i0 = int(idx); frac = idx - i0   # 線形補間
            s = src[i0] * (1 - frac) + src[i0 + 1] * frac
            j = start + i
            if 0 <= j < len(out):
                out[j] += s * win[i] * gain
        pos = (pos + scan * spacing) % limit  # 次の粒は少し先から
        t += spacing
    return out[:total]
```

大事なのは **`pos` と `t` を別々に進めている**こと。`t` が密度（時間軸の刻み）、`pos` が素材の読み出し位置（= scan）。この2つを分けた瞬間に「時間伸縮」と「ピッチシフト」が独立に扱えるようになる。ここが理解の山。

2. 粒長 5ms / 密度 40 / ジッタあり — 重なり 0.2、粒が聞こえるざらつき
3. 粒長 120ms / 密度 8 / scan 0.05 — 重なり 0.96、ゆっくりした雲

## つまずきポイント

- **窓を掛けない → クリック**: 端が0でない波形はインパルスとして鳴る。最初にやるミス。
- **重なりの設計をしない → 音量がうねる**: COLA を外すとトレモロが乗る。`1/(密度×粒長)` で割る、または窓の和で正規化。
- **等間隔に撒きすぎる → バズる**: 粒の周期が音程として聞こえる。ジッタか高密度化で回避。
- **粒長を短くしすぎる → 音程が消える**: 5ms で帯域 355Hz。音程を保ちたいなら 50ms 以上。
- **位置が終端を超える → プツプツ**: ループ／クランプ／フェードのどれかに決める。`idx % limit` を忘れると範囲外アクセス。
- **`rate ≠ 1` で補間なし → エイリアス／ジッパーノイズ**: 整数切り捨てで読むと階段状の歪みが出る。
- **オーディオスレッドで確保する → ノイズ**: 粒ごとに `Vec` を作る実装は RT では使えない。固定プールに。
- **ジッタを入れすぎる → 定位と音程がぼやける**: 空間に撒く用途なら有効、音程を聞かせたいなら控えめに。
- **ステレオで左右の粒を揃える → モノラルに聞こえる**: 広げたいなら粒ごとに位置と位相をずらす。
- **グラニュラー＝キラキラだと思い込む**: 矩形窓＋低密度なら「ザラザラ／ブツブツ」にもなる。窓と密度で性格が変わる。
