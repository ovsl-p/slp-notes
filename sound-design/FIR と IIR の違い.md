# FIR と IIR の違い

## ひとことで

FIR は今の入力を有限個足し合わせるだけ、IIR は過去の出力をフィードバックする。その一点の差が、位相・遅延・安定性・コストのすべてに効いてくる。

## なぜ効くか / どこで使うか

フィルタの構造を選ぶことは、音質の設計そのもの。

- **マスタリング／リニアフェイズEQ**: 波形の形を崩したくない → FIR
- **ライブ・モニター・プラグインの低遅延**: 数msの遅延も許されない → IIR（か短いFIR）
- **クロスオーバー**: スピーカー間の位相整合が要る → IIR（Linkwitz-Riley）か、リニアフェイズFIR
- **アナログ機器のモデリング**: 共鳴（極）で音を作る → IIR
- **コムフィルタ・オールパス・リバーブ**: 遅延フィードバックそのもの → IIR
- **スピーカー／部屋の補正（逆フィルタ）**: 位相まで含めて補正したい → FIR
- **CPUが厳しい組み込み**: 少ない次数で急峻にしたい → IIR

「どっちが良い」ではなく、**位相を犠牲にしてコストを取るか、コストを払って位相を守るか**の選択。

| 知っておくこと | なぜ必要か |
| --- | --- |
| 差分方程式 | フィルタの実体は「過去の入出力の重み付き和」。この式が読めないと何も始まらない |
| インパルス応答と畳み込み | FIR/IIR の名前の由来そのもの。有限か無限かが定義の差 |
| z変換と伝達関数 H(z) | 極と零点で性質が全部決まる。係数がどう音に効くかが見える |
| 極と零点 | 極がフィードバック（IIR）、零点だけなら FIR。安定性は極の位置 |
| 位相・群遅延 | 直線位相かどうかが音の「形」を決める。この文脈で一番重要な概念 |
| サンプリング定理 | ナイキスト以上は扱えない。プリワーピングの話にも繋がる |
| 量子化と固定小数点 | IIR は係数誤差に敏感。DSP 実装ではここで差が出る |

## 本体の解説

### 0. ざっくり言うと

- **IIR は「その場で返事する」フィルタ**。前の出力を次の計算に使い回すので、計算が少なく、遅れがほぼない。その代わり波形の形（位相）は少し崩れる。
- **FIR は「少し待ってから返事する」フィルタ**。入力を N 個ためてから計算するので、計算が多く、必ず遅れる。その代わり、ためた分をきれいに使えば波形の形を崩さずに済む。

音で言えば、IIR はアナログ回路っぽく反応が速い音、FIR は時間をかけて正確に作る音。**「遅れていいかどうか」で選ぶ**のが実務的な判断基準。

### 1. 定義：式で見る

**FIR（Finite Impulse Response）** — 入力だけを使う。

```
y[n] = b0·x[n] + b1·x[n-1] + ... + bN·x[n-N]
```

**IIR（Infinite Impulse Response）** — 過去の出力（フィードバック）を使う。

```
y[n] = b0·x[n] + b1·x[n-1] + ... − a1·y[n-1] − a2·y[n-2] − ...
```

伝達関数で書くと

```
FIR:  H(z) = B(z)          ← 分母が1、つまり極がない（零点だけ）
IIR:  H(z) = B(z) / A(z)   ← 極がある
```

- FIR のインパルス応答は **N+1 サンプルで終わる**（有限）
- IIR のインパルス応答は **理論上永遠に続く**（指数減衰するが0にならない）

この「極があるかどうか」が、以下のすべてを決める。

**「タップ数」の意味**: タップ（tap）はもともとアナログのディレイライン（バケツリレー）の**取り出し口**のこと。デジタルの FIR でも同じで、**タップ数 N = 係数の個数 = インパルス応答の長さ**。N 個のうち1つは遅延0（原音そのまま）なので、**遅延させたコピーは N−1 個**、最大遅延も N−1 サンプル。計算量は1サンプルあたり N 回の積和で、その回数がそのまま「足し合わせる音の数」になる。

**「次数（order）」と「タップ数」は別物**。

- FIR: 次数 = タップ数 − 1（257タップ = 256次）。タップ数の言い換え
- IIR: 次数 = 極の数。2次 = バイクアッド1個、4次 = バイクアッド2個の縦続。タップ数という言い方はしない

そして**次数がそのまま急峻さ**になる（実測、LPF fc=500Hz）:

| 次数 | オクターブあたりの減衰 | カットオフでの減衰 |
| --- | --- | --- |
| 2次 | 12 dB/oct | -3.0 dB |
| 4次 | 24 dB/oct | -6.0 dB |
| 8次 | 48 dB/oct | -12.0 dB |

IIR の「4次」はバイクアッド2個ぶん。FIR で同じ急峻さを出すには数百タップ必要になる（＝次数が数百）。

#### 極（pole）って何？

**極は「フィルタが共鳴する中心」**。数学的には `H(z) = B(z)/A(z)` の**分母が 0 になる点**で、そこでゲインが理論上無限大になる。直感では「**フィードバックが作る反響の閉じ込め**」。

- 極には**角度**と**半径**がある（複素平面上の位置）
- **角度** → 共鳴する周波数（`f = θ·fs/2π`）
- **半径** → 共鳴の鋭さ。**1 に近いほど鋭く、長く響く**

シンセのフィルターでレゾナンスを上げると「ピー」と鳴る、あれが**極を単位円（半径1）に近づけている状態**。実測（LPF fc=1kHz）:

| Q | ピーク | 極の半径 | 聞こえ方 |
| --- | --- | --- | --- |
| 0.71 | -0.26 dB（ピークなし） | 0.912 | 素直なローパス |
| 5 | +14.0 dB @ 990Hz | 0.987 | レゾナンスが出る |
| 20 | +26.0 dB @ 1kHz | 0.997 | 笛のように鳴る |

半径が **1 を超えると発散**（不安定）。だから IIR では極の位置が常に問題になる。FIR は分母が 1（＝極がない。全部 z=0 の原点にある）ので、**不安定になりようがない**。

ブランコのたとえが近い。押すタイミングが合うと（共鳴周波数）どんどん大きくなり、摩擦が小さい（極が単位円に近い）ほど大きく響く。押しすぎると制御不能（発散）。

#### カットオフと Q は、極のどこを動かすノブか

よくある誤解が「カットオフを動かす＝可聴域外のノッチの Q を変えている」。実際は**別々のつまみ**で、動く場所が違う。

実測（2次ローパス、零点と極の位置を計算したもの）:

**カットオフを動かす（Q=0.707 固定）**

| fc | 極の角度 | 極の半径 | 零点 |
| --- | --- | --- | --- |
| 200Hz | 1.06° | 0.982 | -1.0（固定） |
| 1kHz | 5.32° | 0.912 | -1.0（固定） |
| 5kHz | 28.5° | 0.631 | -1.0（固定） |
| 10kHz | 69.3° | 0.434 | -1.0（固定） |

**Q を動かす（fc=1kHz 固定）**

| Q | 極の角度 | 極の半径 |
| --- | --- | --- |
| 0.71 | 5.32° | 0.912 |
| 5 | 7.46° | 0.987 |
| 20 | 7.50° | 0.997 |

読み取れること:

- **カットオフ = 極の角度を回すノブ**（＝共鳴する周波数・曲がり始める位置を動かす）。半径も副次的に動く
- **Q = 極の半径を外に出すノブ**（＝鋭さを変える）。角度はほぼ動かない
- **零点は z = −1（24kHz = ナイキスト）に固定**。ローパスの「高域が落ち続ける」性質はこの零点が作っていて、**カットオフを動かしても零点は動かない**

つまりローパスは「ノッチを可聴域の外に置いているフィルタ」ではなく、**極で曲がりを作り、ナイキストの零点で落とし続ける**構造。ノッチフィルタ（帯域除去）はまた別の設計で、零点を単位円上に置いたもの。

実務では、カットオフを動かすときは**係数を再計算している**（＝極を動かしている）。急に動かすとフィルタの内部状態が飛んでクリックが出るので、**パラメータは補間して滑らかに動かす**。

#### なぜ「足し算」でフィルタになるのか

「入力を足すだけなら、元の音が大きくなるだけでは？」という疑問はもっとも。答えは **足す前に「遅らせて」いるから**。

`y[n] = b0·x[n] + b1·x[n-1]` は、**今の音と1サンプル前の音**を足している。この2つは同じ音ではない。遅れ k サンプルは、周波数 f に対して `2πfk/fs` の位相ズレになる。つまり **遅延 = 周波数に比例した位相ズレ**。

- **低い周波数**: 1サンプルの遅れはごく小さい位相ズレ → 2つの波はほぼ同相 → 強め合う（通す）
- **高い周波数**: 位相ズレが180°に近づく → 逆相 → 打ち消し合う（止める）

これがローパスの正体。「大きくなる」のは **0Hz（DC）だけ**で、それ以外は周波数ごとにゲインが違う。だから音量が一様に上がるのではなく、**周波数によって通したり消したりする**。

実測（48kHz、係数和が1になるよう正規化したフィルタに正弦波を通し、出力/入力の振幅比を測ったもの）:

**4タップ箱型（`0.25, 0.25, 0.25, 0.25`）**

| 周波数 | 出力/入力 |
| --- | --- |
| 0 Hz | 0.00 dB |
| 100 Hz | -0.00 dB |
| 1 kHz | -0.09 dB |
| 4 kHz | -1.55 dB |
| 8 kHz | -7.27 dB |
| 10 kHz | -13.75 dB |
| 12 kHz | **-229 dB（完全に消える）** |

**2タップくし型（1ms = 48サンプル遅らせて足す）**

| 周波数 | 出力/入力 |
| --- | --- |
| 0 Hz | 0.00 dB |
| 250 Hz | -3.01 dB |
| 500 Hz | **-254 dB（消える）** |
| 1 kHz | 0.00 dB |
| 1.5 kHz | **-244 dB（消える）** |
| 2 kHz | 0.00 dB |

同じ「足し算」なのに、500Hz は消えて 1kHz はそのまま通る。これがフィルタ。1ms 遅らせて足すだけで作れるこのくし型が、**フランジャー**の原理でもある。

つまりフィルタ設計とは、**「どの周波数を同相で足し、どの周波数を逆相で消すか」を係数で決めること**。係数和が DC ゲイン（音量）で、係数の並びが周波数ごとの足し具合を決める。

#### すべての FIR は「コムの重ね合わせ」

ここまでくると「じゃあ全部コムフィルタでは？」という疑問が出る。**構造としてはその通り**で、FIR は「遅延長の違うコムをたくさん足し合わせたもの」。各タップが「k サンプル遅らせたコピー」なので、原理は全部いっしょ。

違うのは **ノッチの間隔と深さ**。間隔は `SR / 遅延サンプル数` で決まる。

| フィルタ | ノッチの間隔 | 耳での聞こえ方 |
| --- | --- | --- |
| 1サンプル遅延（20.8µs） | ノッチは 24kHz 付近 | 聴こえない（可聴域の外） |
| 1ms 遅延（48サンプル） | 1kHz ごと（実測: 500 / 1500 / 2500Hz が消える） | はっきりコム。フランジャーそのもの |
| 4タップ箱型 | 12kHz に1つだけ | ほぼ気づかない |
| 257タップ LP | 阻止域に `SR/257 ≒ 187Hz` 間隔（実測 -75〜-86dB） | 通過域が平坦なのでコムに聞こえない |

つまり **フィルタ設計とは「ノッチを聴こえない場所（阻止域）に閉じ込めて、通過域を平坦にする」作業**。実測だと、257タップの通過域 20〜600Hz の偏差は **0.056dB**（ほぼ完全に平ら）。多数のコムが干渉し合った結果、通過域では打ち消し合ってフラットになっている。

逆に「コムが欲しい」ときは遅延を長くする（1ms 以上）。IIR のコム（フィードバック付き）はノッチがより深く鋭くなる。

#### 「坂」と「コム」は同じものの2つの見え方

「LPF は坂なのに、原理はコム？」という引っかかりは、**歯（ノッチ）の間隔が細かすぎて見えなくなる**ことで解ける。

まず、**2タップ（原音 + D サンプル遅らせたコピー）**だけで考える。この応答は `|cos(πfD/fs)|` で、山谷の数は「その遅延が位相を何回転させるか」で決まる。

| D（サンプル） | 遅延 | 0→20kHz の位相回転 | ノッチの本数 | 見え方 |
| --- | --- | --- | --- | --- |
| 1 | 0.02ms | 0.4 回転 | 0本 | **なだらかな坂**（ノッチは24kHzに1個だけ） |
| 4 | 0.08ms | 1.7 回転 | 2本 | まだ坂 |
| 16 | 0.33ms | 6.7 回転 | 7本 | うねりが見え始める |
| 48 | 1.0ms | 20 回転 | 20本 | **はっきりコム** |
| 257 | 5.4ms | 107 回転 | 107本 | 歯が細かすぎて坂に見える |

**D=1 サンプルなら、0〜20kHz で位相はまだ半回転もしていない。** だから山谷が1つも入らず、ただのなだらかな坂になる。これが「1サンプル遅らせて足す」フィルタの正体で、コムにはならない。

遅延を長くすると位相が何回も回り、強め合う点と打ち消す点が交互に現れる → コム。**歯の本数 ≒ 遅延サンプル数 × 0.8** くらいのイメージ。

多タップの FIR は、**D の違うコムをたくさん足し合わせたもの**。足し合わせると山谷が平均化されて、滑らかな坂（＝通過域と阻止域の形）になり、細かいリップルだけが残る。N=257 の場合、そのリップルは 187Hz 間隔で -75〜-86dB。**間隔が細かく、深さも浅いので、耳にも目にも「坂」に見える**。

つまり:

- **コム** = 歯の間隔が広くて、1本1本が聞き取れる状態（遅延が長い）
- **坂** = 歯が細かすぎて平均化され、包絡線だけが見える状態（遅延が短い／多数タップ）

同じ干渉を、粗さの違うスケールで見ているだけ。

#### なぜハイパスは低域が消えるのか

**ローパスが「足し算」なら、ハイパスは「引き算」**。違いはそれだけ。

```
ローパス:  y[n] = 0.5·x[n] + 0.5·x[n-1]    ← 足す
ハイパス:  y[n] = 0.5·x[n] − 0.5·x[n-1]    ← 引く
```

低い音は1サンプルの間で値がほとんど変わらない。だから**差を取るとほぼ0になる**。0Hz（直流）に至っては完全に0。

- 足し算 → 低域は同相で強め合う（通る）
- 引き算 → 低域は同相だから打ち消し合う（消える）

位相で言い直すと、**引き算はコピーの位相を180°反転して足すこと**。DC はコピー間に位相差がないので、反転した瞬間に完全な逆相になって必ず消える。逆にナイキスト（fs/2）はコピー同士が180°ズレているので、反転すると同相になって通る。

実測（48kHz、`0.5, -0.5` の2タップ）:

| 周波数 | ゲイン |
| --- | --- |
| 0 Hz | **-240 dB（完全に0）** |
| 20 Hz | -57.7 dB |
| 100 Hz | -43.7 dB |
| 1 kHz | -23.7 dB |
| 5 kHz | -9.9 dB |
| 20 kHz | -0.3 dB |

一定値（DC）を入力して出力の最大値を測ると **0.0**（完全に消える）。

多タップでも同じで、**ハイパスは「デルタ − ローパス」**として作れる（スペクトル反転）。実測（N=257、fc=1kHz）:

- 0Hz: -240dB、100Hz: -80.4dB、500Hz: -74.2dB、1kHz: -6.0dB、5kHz: 0.0dB

そして **LPF + HPF の応答を足すと全周波数でちょうど 1.0** になる（実測で誤差 1e-15 オーダー）。つまりハイパスは「ローパスが通した分を、元の音から差し引いた残り」。**引き算でできている**ことがそのまま数字に出る。

実務での注意:

- ハイパスは位相が反転する（絶対位相が180°ずれる）。ローパスと並列に混ぜると打ち消し合って音が消えることがある
- 「消える」のは DC だけで、実際は坂。20Hz 以下をきっちり落としたいなら次数を上げる（＝遅延が増える）
- 2次のハイパスは 6dB/oct（実測でも 100Hz -43.7dB → 1kHz -23.7dB で約 20dB/decade）

### 2. 位相：ここが最大の違い

**FIR は係数を対称（`b[k] = b[N-k]`）にすると直線位相になる。** 群遅延は全周波数で `(N-1)/2` サンプル一定。手元で実測した値（N=65, fc=1kHz）：

| 周波数 | FIR の群遅延 |
| --- | --- |
| 100Hz | 32.0 samples |
| 1kHz | 32.0 samples |
| 4kHz | 32.0 samples |
| 10kHz | 32.0 samples |

**IIR は（オールパス以外）非直線位相。** 同じ fc=1kHz の1極IIRを実測すると：

| 周波数 | IIR の群遅延 |
| --- | --- |
| 100Hz | 7.1 samples |
| 1kHz | 3.3 samples |
| 4kHz | 0.0 samples |

つまり **低域は遅く、高域は速い**。これが「IIR フィルタを通すとトランジェントがぼける／プリリンギングが変わる」原因。直線位相なら波形の形が保たれる（全成分が同じだけ遅れる＝形が変わらない）。

ただし直線位相には代償がある。**遅延が必ず `(N-1)/2` サンプル出る**。48kHz で N=257 なら **2.67ms**。マスタリングなら問題ないが、ライブのモニターや演奏系プラグインでは致命的。

### 3. 遅延（レイテンシ）

**FIR（直線位相）の遅延は `(N-1)/2` サンプル。ローパスでもハイパスでも同じ**。遅延を決めるのは「種類」ではなく「次数」だけ。実測（48kHz、同じタップ数で LP と HP を作って群遅延を測ったもの）:

| タップ数 N | 遅延（サンプル） | 48kHz で | 44.1kHz で |
| --- | --- | --- | --- |
| 65 | 32 | 0.67 ms | 0.73 ms |
| 129 | 64 | 1.33 ms | 1.45 ms |
| 257 | 128 | 2.67 ms | 2.90 ms |
| 513 | 256 | 5.33 ms | 5.80 ms |
| 1025 | 512 | 10.67 ms | 11.61 ms |

実測でも LP（300Hz で測定）と HP（3kHz で測定）がぴったり同じ値になった。**急峻さが欲しいなら N を増やす＝遅延が増える**、がトレードオフ。

**IIR の遅延は「1つの数字」では表せない**（周波数で変わる群遅延）。実測（2次バタワース、fc=1kHz）:

| 周波数 | 群遅延（サンプル） |
| --- | --- |
| 50Hz | 10.8 |
| 500Hz | 12.7（カットオフ付近で最大） |
| 1kHz | 10.8 |
| 2kHz | 3.2 |
| 5kHz | 0.5 |

つまり通過域では **約 0.2ms**、カットオフ付近で少し増え、高域ではほぼゼロ。次数を上げると比例して増える（同じ fc=1kHz で 2次=10.8 / 4次=21.6 / 8次=43.3 サンプル ≒ 0.9ms）。

- **FIR**: 全帯域で一定の遅延（波形の形が保たれる代償）
- **IIR**: 遅延は小さいが周波数で変わる（波形の形が崩れる代償）
- **ゼロ遅延FIR**: 係数を非対称にして位相を犠牲にすれば遅延を減らせる（その代わり直線位相でなくなる）

並列処理（ドライ／ウェット、2way クロスオーバー）では**遅延差が位相ズレになる**ので、どちらかに遅延を足して揃える必要がある。

### 4. 安定性

- **FIR は常に安定。** 極がないので、係数がどうであれ発散しない。設計ミスが「音が変」で済む
- **IIR は極が単位円の内側（|極| < 1）でないと発散する。** フィードバックがあるので、係数の丸め誤差・固定小数点・パラメータの急変で不安定化しうる

実装では**フィルタの状態（過去の入出力）を保持する**必要があるのも IIR 側。状態をリセットし忘れると、前の音の残りがプツッと出る。

### 5. 次数とコスト

同じ急峻さを得るのに必要な次数が桁違い。

- **IIR（2次バタワース）** = 12dB/oct。1kHz カットオフを実測すると 1kHz で -3.01dB、2kHz で -12.37dB、4kHz で -24.48dB
- **FIR** = 同じ急峻さを狙うと数百タップ。N=257（fc=1kHz）で 1kHz -6.0dB、1.5kHz -69dB

1サンプルあたりの演算は：

- FIR N=257 → **257回の積和**
- バイクアッド（2次IIR）→ **5回の積和 + 状態4個**

**約50倍の差**。ただし FIR は **FFT畳み込み**（ブロック畳み込み）で長いものを効率化できるので、N が数百を超えるなら FFT 側が有利になってくる。

### 6. 設計法

**FIR**
- 窓関数法: sinc に窓（Hann/Blackman/Kaiser）を掛ける。直感的で実装が簡単
- Parks-McClellan（Remez）: 等リップル最適設計。通過域と阻止域のリップルを指定して最適化
- 最小二乗法: 周波数特性の誤差を最小化

**IIR**
- アナログプロトタイプ（バタワース／チェビシェフ／楕円）を設計
- **双一次変換**でデジタル化。ここで周波数ワープが起きるので **プリワーピング**が必要（`tan(π·fc/fs)` で補正しないとカットオフがずれる）
- バイクアッド（2次）の縦続で高次を組む（数値安定性のため）

### 7. どのエフェクトがどっち向きか

| エフェクト | 向いてる方 | 理由 |
| --- | --- | --- |
| ふつうの EQ（パラメトリック） | **IIR** | 遅延ゼロ・CPU軽い。音の変化が自然 |
| マスタリング用 EQ（リニアフェイズ） | **FIR** | 波形の形を崩さない。遅延は許容できる |
| コンプレッサー／リミッター | **IIR** | 反応速度が命。内部の検波・スムージングで使う |
| コーラス／フランジャー／フェイザー | **IIR** | 短い遅延線とオールパス（＝IIR構造）で作るのが定番 |
| アルゴリズムリバーブ | **IIR** | コムフィルタ＋オールパスのフィードバックそのもの |
| コンボリューションリバーブ | **FIR** | 測ったインパルス応答を畳み込む処理。IR は FIR の係数そのもの |
| キャビネットIR／アンプシミュ | **FIR** | スピーカーや部屋の IR を畳み込む（IRローダーの実体） |
| シンセのフィルター（VCF）／オートワウ | **IIR** | 極の共鳴が音の正体。パラメータを動かしやすい |
| クロスオーバー（マルチバンド） | **IIR**（LR4）or **FIR** | 低遅延優先なら IIR、位相整合優先なら FIR |
| サンプルレート変換／アンチエイリアス | **FIR** | 急峻さと位相を設計したい |
| スピーカー／部屋の補正（逆フィルタ） | **FIR** | 位相まで含めて狙った特性を作れる |
| ディストーション | **IIR**（内部） | 後段のトーン調整とアンチエイリアスに使う |

覚え方はひとつだけ：**遅らせていいなら FIR、遅らせたら困るなら IIR**。

身近な例で言うと、**コンボリューションリバーブやギターのキャビネットIRは FIR**（IR を畳み込む＝FIR そのもの）、**シンセのフィルターやコーラス、アルゴリズムリバーブは IIR**（共鳴とフィードバックで音を作る）。

## 具体例・コード

### FIR（窓付き sinc、直線位相）

```python
import math

def fir_lowpass(N, fc, sr=48000.0):
    """N タップの窓付き sinc ローパス（Blackman 窓）。係数は対称になる"""
    M = N - 1
    h = []
    for n in range(N):
        k = n - M / 2
        s = 2 * fc / sr
        val = s if k == 0 else math.sin(2 * math.pi * fc / sr * k) / (math.pi * k)
        w = 0.42 - 0.5 * math.cos(2 * math.pi * n / M) + 0.08 * math.cos(4 * math.pi * n / M)
        h.append(val * w)
    g = sum(h)                       # DC ゲインを 1 に正規化
    return [x / g for x in h]

h = fir_lowpass(257, 1000.0)
print(len(h), h[0] == h[-1])          # 257 True（対称 = 直線位相）
print("群遅延 =", (len(h) - 1) / 2, "samples =", (len(h) - 1) / 2 / 48.0, "ms")
```

### IIR（1極）と IIR（2次バタワース／バイクアッド）

```python
import math, cmath

SR = 48000.0

# --- 1極ローパス: y[n] = (1-a)x[n] + a·y[n-1]
a = math.exp(-2 * math.pi * 1000.0 / SR)      # 0.8773 → 1kHz で -3dB

# --- 2次バタワース（RBJ Audio EQ Cookbook の LPF）
fc, Q = 1000.0, 1 / math.sqrt(2)
w0 = 2 * math.pi * fc / SR
alpha = math.sin(w0) / (2 * Q)
cw = math.cos(w0)
a0 = 1 + alpha
b0 = ((1 - cw) / 2) / a0
b1 = (1 - cw) / a0
b2 = ((1 - cw) / 2) / a0
a1 = (-2 * cw) / a0
a2 = (1 - alpha) / a0

def H_biquad(f):
    z = cmath.exp(-1j * 2 * math.pi * f / SR)
    return (b0 + b1 * z + b2 * z * z) / (1 + a1 * z + a2 * z * z)

for f in (100, 1000, 2000, 4000):
    print(f, "%.2f dB" % (20 * math.log10(abs(H_biquad(f)))))
# 100 -0.00 / 1000 -3.01 / 2000 -12.37 / 4000 -24.48
```

実測値（48kHz、カットオフ1kHz）：

| | FIR N=257 | IIR 1極 | IIR 2次バタワース |
| --- | --- | --- | --- |
| 1kHz での減衰 | -6.0dB | -3.0dB | -3.0dB |
| 2kHz での減衰 | -83.9dB | -7.0dB | -12.4dB |
| 4kHz での減衰 | -106dB | -12.2dB | -24.5dB |
| 群遅延 | 128 samples 一定 | 7.1→0 samples | 周波数依存 |
| 演算／サンプル | 257 積和 | 2 積和 | 5 積和 |
| 遅延 | 2.67ms | 0.15ms | 数サンプル |

![[assets/sound-design/fir-vs-iir-response.svg]]

上段が振幅特性、下段がインパルス応答（dB）。FIR は 257タップで**ぶつりと終わる**、IIR は**指数減衰で続く**（dB では直線）。この「有限か無限か」が定義そのもの。

### 聴き比べ用のデモ

同じ素材（ベース＋パッド＋ハイハット）を4通りに通したもの。各2秒、間に無音。

1. **原音**（ドライ）
2. **LPF 4次 500Hz** — 足し算。低域が残り、ハイハットが消える
3. **HPF 4次 1.5kHz** — 引き算。ベースとパッドの低域が消えて、ハイハットだけ残る
4. **コム 1ms**（原音＋1ms遅れを50:50）— 音程感のある金属的なうねり

![[assets/sound-design/filter_demo.mp3]]

高域の量を数値で測ると（一次差分の RMS ÷ 信号の RMS、大きいほど明るい）: 原音 0.121 / LPF 0.020 / HPF 1.491 / コム 0.093。LPF で暗くなり、HPF で極端に明るくなり、コムは少し暗くなる（ノッチで高域が削られるため）。

## つまずきポイント

- **「FIR は直線位相」は係数が対称なときだけ**。非対称 FIR（ゼロ遅延FIRなど）は非直線位相。
- **直線位相の遅延を補償し忘れる**。ドライ音と並べると位相がズレて「薄く」聞こえる。
- **IIR の極を1に近づけすぎる**。ゲインが発散し、係数の丸めで発振する。固定小数点では特に危険。
- **プリワーピングを忘れる**。双一次変換は高域が圧縮されるので、`tan` 補正なしだとカットオフが狙った位置とずれる。
- **フィルタ状態の初期化漏れ**。前の音の状態が残って、無音のはずの場所でプツッと鳴る。
- **係数を a0 で正規化し忘れる**（RBJ の式は a0 で割る）。
- **急なパラメータ変更**で状態が飛ぶ（IIR は特に）。補間して動かす。
- **FFT畳み込みの遅延**を考えない。ブロック長とパーティションで遅延が変わる。
- **「IIR のほうが少ない次数で済む＝常に優れている」わけではない**。位相と安定性を引き換えにしている。
