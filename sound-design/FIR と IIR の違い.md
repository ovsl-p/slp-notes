# FIR と IIR の違い

## ひとことで

FIR は今の入力を有限個足し合わせるだけ、IIR は過去の出力をフィードバックする。その一点の差が、位相・遅延・安定性・コストのすべてに効いてくる。

## なぜ効くか / どこで使うか

フィルタの構造を選ぶことは、音質の設計そのものになる。位相を犠牲にしてコストを取るか、コストを払って位相を守るかの選択になる。

マスタリングの EQ のように波形の形を崩したくない場面では FIR を選び、ライブのモニターのように数msの遅延も許されない場面では IIR を選ぶ。どれがどちらに向くかは、このノートの後半にエフェクト別の表としてまとめてある。

| 知っておくこと | なぜ必要か |

## 本体の解説

### 0. ざっくり言うと

IIR は前の出力を次の計算に使い回すので、計算が少なく遅れがほぼない。その代わり波形の形（位相）は少し崩れる。

FIR は入力を N 個ためてから計算するので、計算が多く必ず遅れる。その代わり、ためた分をきれいに使えば波形の形を崩さずに済む。

音で言えば、IIR はアナログ回路に近い反応の速い音、FIR は時間をかけて正確に作る音になる。

### 1. 定義：式で見る

**FIR（Finite Impulse Response）**は入力だけを使うフィルタで、出力は次の式で書ける。

```
y[n] = b0·x[n] + b1·x[n-1] + ... + bN·x[n-N]
```

**IIR（Infinite Impulse Response）**は過去の出力（フィードバック）も使うフィルタになる。

```
y[n] = b0·x[n] + b1·x[n-1] + ... − a1·y[n-1] − a2·y[n-2] − ...
```

伝達関数で書くと、FIR は分母が 1 で極を持たず零点だけになり、IIR は分母を持つので極が生まれる。

```
FIR:  H(z) = B(z)          ← 分母が1、つまり極がない（零点だけ）
IIR:  H(z) = B(z) / A(z)   ← 極がある
```

FIR のインパルス応答は N+1 サンプルで終わり、IIR のインパルス応答は理論上永遠に続く（指数減衰するが0にならない）。この極があるかどうかが、位相・遅延・安定性・コストのすべてを決める。

タップ（tap）はもともとアナログのディレイライン（バケツリレー）の取り出し口を指す言葉で、デジタルの FIR でも同じ意味になる。タップ数 N は係数の個数、インパルス応答の長さにあたる。N 個のうち1つは遅延0（原音そのまま）なので、遅延させたコピーは N−1 個になり、最大遅延も N−1 サンプルになる。計算量は1サンプルあたり N 回の積和で、その回数が足し合わせる音の数になる。

次数とタップ数は別物になる。FIR では次数がタップ数から1を引いた値で、257タップなら256次にあたる。IIR では次数が極の数になり、2次はバイクアッド（2次のIIRフィルタを1ブロックにまとめた形）1個、4次はその2個の縦続を指す。

次数がそのまま急峻さになる（実測、LPF fc=500Hz）:

| 次数 | オクターブあたりの減衰 | カットオフでの減衰 |
| --- | --- | --- |
| 2次 | 12 dB/oct | -3.0 dB |
| 4次 | 24 dB/oct | -6.0 dB |
| 8次 | 48 dB/oct | -12.0 dB |

FIR で同じ急峻さを出すには数百タップが要り、次数もその数になる。

### 2. 位相：ここが最大の違い

FIR は係数を対称（`b[k] = b[N-k]`）にすると直線位相になり、群遅延は全周波数で `(N-1)/2` サンプル一定になる。手元で実測した値（N=65, fc=1kHz）:

| 周波数 | FIR の群遅延 |
| --- | --- |
| 100Hz | 32.0 samples |
| 1kHz | 32.0 samples |
| 4kHz | 32.0 samples |
| 10kHz | 32.0 samples |

IIR は一般に非直線位相になる。オールパス（振幅を変えず位相だけ回すフィルタ）は位相を意図的に回すためのものなので、これも非直線位相になる。同じ fc=1kHz の1極IIRを実測すると、100Hz が 7.1 サンプル、1kHz が 3.3 サンプル、4kHz が 0.0 サンプルになる。

低域は遅く、高域は速い。IIR でトランジェントがぼけるのはこの位相ズレのためになる。逆に直線位相 FIR は、対称なインパルス応答のぶんだけプリリンギング（本来の音より前に出る鳴り）が出る。直線位相なら全成分が同じだけ遅れるので、波形の形が保たれる。

直線位相には代償があり、遅延が必ず `(N-1)/2` サンプル出る。48kHz で N=257 なら 2.67ms になり、マスタリングでは問題ないが、ライブのモニターや演奏系プラグインでは致命的になる。

### 3. 遅延（レイテンシ）

直線位相の FIR では、遅延が `(N-1)/2` サンプルになる。ローパスでもハイパスでも同じで、遅延を決めるのは種類ではなく次数になる。実測（48kHz、同じタップ数で LP と HP を作って群遅延を測ったもの）:

| タップ数 N | 遅延（サンプル） | 48kHz で | 44.1kHz で |
| --- | --- | --- | --- |
| 65 | 32 | 0.67 ms | 0.73 ms |
| 129 | 64 | 1.33 ms | 1.45 ms |
| 257 | 128 | 2.67 ms | 2.90 ms |
| 513 | 256 | 5.33 ms | 5.80 ms |
| 1025 | 512 | 10.67 ms | 11.61 ms |

実測でも LP（300Hz で測定）と HP（3kHz で測定）がぴったり同じ値になった。N を増やすと急峻になるが、そのぶん遅延も増える。

IIR の遅延は1つの数字では表せず、周波数で変わる群遅延になる。実測（2次バタワース、fc=1kHz）:

| 周波数 | 群遅延（サンプル） |
| --- | --- |
| 50Hz | 10.8 |
| 500Hz | 12.7 |
| 650Hz | 13.0（最大） |
| 1kHz | 10.8 |
| 2kHz | 3.2 |
| 5kHz | 0.5 |

通過域では約 0.2ms になり、650Hz 付近で最大 13.0 サンプルまで増え、高域ではほぼゼロになる。次数を上げると比例して増え、同じ fc=1kHz で 2次が 10.8、4次が 21.6、8次が 43.3 サンプル（約 0.9ms）になる。

FIR は全帯域で一定の遅延になり、波形の形が保たれる代償としてこの遅延を払う。IIR は遅延が小さい代わりに周波数で変わり、波形の形が崩れる。ゼロ遅延FIR は係数を非対称にして位相を犠牲にすれば遅延を減らせるが、直線位相ではなくなる。

並列処理（ドライとウェット、2way クロスオーバー）では遅延差が位相ズレになるので、どちらかに遅延を足して揃える必要がある。

### 4. 安定性

FIR は極を持たないので、係数がどうであれ発散せず常に安定する。設計ミスが音の変化で済む。

IIR は極が単位円の内側（|極| < 1）でないと発散する。フィードバックがあるので、係数の丸め誤差・固定小数点・パラメータの急変で不安定化しうる。

実装ではフィルタの状態（過去の入出力）を保持する必要があるのも IIR 側になる。状態をリセットし忘れると、前の音の残りがプツッと出る。

### 5. 次数とコスト

同じ急峻さを得るのに必要な次数が桁違いになる。

IIR の2次バタワースは 12dB/oct で、1kHz カットオフを実測すると 1kHz が -3.01dB、2kHz が -12.37dB、4kHz が -24.48dB になる。FIR で同じ急峻さを狙うと数百タップが必要で、N=257（fc=1kHz）では 1kHz が -6.0dB、1.5kHz が -69dB になる。

1サンプルあたりの演算は、FIR の N=257 で257回の積和、バイクアッド（2次IIR）で5回の積和と状態4個になる。約50倍の差が出る。

FIR は FFT畳み込み（ブロック畳み込み）で長いものを効率化できるので、N が数百を超えるなら FFT 側が有利になってくる。

### 6. 設計法

FIR の設計法には3つある。窓関数法は sinc に窓（Hann、Blackman、Kaiser）を掛ける方法で、直感的で実装が簡単になる。Parks-McClellan（Remez）は等リップル最適設計で、通過域と阻止域のリップルを指定して最適化する。最小二乗法は周波数特性の誤差を最小化する。

IIR はアナログプロトタイプ（バタワース、チェビシェフ、楕円）を設計し、双一次変換でデジタル化する。このとき周波数ワープが起きるので、プリワーピングが必要になる（`tan(π·fc/fs)` で補正しないとカットオフがずれる）。高次はバイクアッドの縦続で組み、数値安定性を確保する。

### 7. どのエフェクトがどっち向きか

| エフェクト | 向いてる方 | 理由 |
| --- | --- | --- |
| ふつうの EQ（パラメトリック） | IIR | 遅延ゼロ・CPU軽い。音の変化が自然 |
| マスタリング用 EQ（リニアフェイズ） | FIR | 波形の形を崩さない。遅延は許容できる |
| コンプレッサー／リミッター | IIR | 反応速度が命。内部の検波・スムージングで使う |
| コーラス／フランジャー／フェイザー | IIR | 短い遅延線とオールパスで作るのが定番 |
| アルゴリズムリバーブ | IIR | コムフィルタとオールパスのフィードバックそのもの |
| コンボリューションリバーブ | FIR | 測ったインパルス応答を畳み込む処理。IR は FIR の係数そのもの |
| キャビネットIR／アンプシミュ | FIR | スピーカーや部屋の IR を畳み込む（IRローダーの実体） |
| シンセのフィルター（VCF、電圧制御フィルタ）／オートワウ | IIR | 極の共鳴が音の正体。パラメータを動かしやすい |
| クロスオーバー（マルチバンド） | IIR（Linkwitz-Riley 4次）か FIR | 低遅延優先なら IIR、位相整合優先なら FIR |
| サンプルレート変換／アンチエイリアス | FIR | 急峻さと位相を設計したい |
| スピーカー／部屋の補正（逆フィルタ） | FIR | 位相まで含めて狙った特性を作れる |
| ディストーション | IIR（内部） | 後段のトーン調整とアンチエイリアスに使う |

身近な例では、コンボリューションリバーブやギターのキャビネットIRが FIR（IR を畳み込む処理そのもの）、シンセのフィルターやコーラス、アルゴリズムリバーブが IIR（共鳴とフィードバックで音を作る）になる。

**遅らせていいなら FIR、遅らせたら困るなら IIR。**

## 具体例・コード

### FIR（窓付き sinc、直線位相）

```python
import math

def fir_lowpass(N, fc, sr=48000.0):
    """N タップの窓付き sinc ローパス（Blackman 窓）。係数は対称になる"""
    M = N - 1
    h = []
    for n in range(N):
        k = n - M / 2
        s = 2 * fc / sr
        val = s if k == 0 else math.sin(2 * math.pi * fc / sr * k) / (math.pi * k)
        w = 0.42 - 0.5 * math.cos(2 * math.pi * n / M) + 0.08 * math.cos(4 * math.pi * n / M)
        h.append(val * w)
    g = sum(h)                       # DC ゲインを 1 に正規化
    return [x / g for x in h]

h = fir_lowpass(257, 1000.0)
print(len(h), h[0] == h[-1])          # 257 True（対称 = 直線位相）
print("群遅延 =", (len(h) - 1) / 2, "samples =", (len(h) - 1) / 2 / 48.0, "ms")
```

### IIR（1極）と IIR（2次バタワース／バイクアッド）

```python
import math, cmath

SR = 48000.0

# --- 1極ローパス: y[n] = (1-a)x[n] + a·y[n-1]
a = math.exp(-2 * math.pi * 1000.0 / SR)      # 0.8773 → 1kHz で -3dB

# --- 2次バタワース（RBJ Audio EQ Cookbook の LPF）
fc, Q = 1000.0, 1 / math.sqrt(2)
w0 = 2 * math.pi * fc / SR
alpha = math.sin(w0) / (2 * Q)
cw = math.cos(w0)
a0 = 1 + alpha
b0 = ((1 - cw) / 2) / a0
b1 = (1 - cw) / a0
b2 = ((1 - cw) / 2) / a0
a1 = (-2 * cw) / a0
a2 = (1 - alpha) / a0

def H_biquad(f):
    z = cmath.exp(-1j * 2 * math.pi * f / SR)
    return (b0 + b1 * z + b2 * z * z) / (1 + a1 * z + a2 * z * z)

for f in (100, 1000, 2000, 4000):
    print(f, "%.2f dB" % (20 * math.log10(abs(H_biquad(f)))))
# 100 -0.00 / 1000 -3.01 / 2000 -12.37 / 4000 -24.48
```

実測値（48kHz、カットオフ1kHz）:

| | FIR N=257 | IIR 1極 | IIR 2次バタワース |
| --- | --- | --- | --- |
| 1kHz での減衰 | -6.0dB | -3.0dB | -3.0dB |
| 2kHz での減衰 | -83.9dB | -7.0dB | -12.4dB |
| 4kHz での減衰 | -106dB | -12.2dB | -24.5dB |
| 群遅延 | 128 samples 一定 | 7.1→0 samples | 周波数依存 |
| 演算／サンプル | 257 積和 | 2 積和 | 5 積和 |
| 遅延 | 2.67ms | 0.15ms | 数サンプル |

![[assets/sound-design/fir-vs-iir-response.svg]]

上段が振幅特性、下段がインパルス応答（dB）。FIR は 257タップでぶつりと終わり、IIR は指数減衰で続く（dB では直線）。有限か無限かが、そのまま定義の違いになっている。

### 聴き比べ用のデモ

同じ素材（ベース、パッド、ハイハット）を4通りに通したもの。各2秒で、間に無音が入る。

1. 原音（ドライ）
2. LPF 4次 500Hz。足し算で、低域が残りハイハットが消える
3. HPF 4次 1.5kHz。引き算で、ベースとパッドの低域が消えてハイハットだけ残る
4. コム 1ms（原音と1ms遅れを50:50）。音程感のある金属的なうねりが出る

![[assets/sound-design/filter_demo.mp3]]

高域の量を数値で測ると（一次差分の RMS を信号の RMS で割った値で、大きいほど明るい）、原音が 0.121、LPF が 0.020、HPF が 1.491、コムが 0.093 になる。LPF で暗くなり、HPF で極端に明るくなり、コムはノッチで高域が削られるぶん少し暗くなる。

## つまずきポイント

- FIR が常に直線位相だと思う。直線位相になるのは係数が対称なときだけで、非対称 FIR（ゼロ遅延FIRなど）は非直線位相になる。
- 直線位相の遅延を補償し忘れる。ドライ音と並べると位相がズレて薄く聞こえる。
- プリワーピングを忘れる。双一次変換は高域が圧縮されるので、`tan` 補正なしだとカットオフが狙った位置とずれる。
- フィルタ状態の初期化を忘れる。前の音の状態が残って、無音のはずの場所でプツッと鳴る。
- 係数を a0 で正規化し忘れる（RBJ の式は a0 で割る）。
- パラメータを急に変える。IIR は状態が飛びやすいので、補間して動かす。
- FFT畳み込みの遅延を考えない。ブロック長とパーティションで遅延が変わる。
- IIR のほうが少ない次数で済むから常に優れている、と思う。位相と安定性を引き換えにしている。
